# 长期来源复核记录

本契约把可迁移的整理记录与原材料分开；原材料放在缓存目录不代表可以重建或删除。只在来源笔记已按内容保全规则复核后维护记录；历史记录不代替本次原文/原媒体检查。

## 位置与边界

- 从共享配置读取可选 `source_evidence`。未配置时旧笔记仍可读、原结构检查可运行；创建新的长期记录前需要明确配置，不用环境变量或另一个目录暗中兜底。
- 每个稳定来源ID在该目录下有一份 `record.json` 与供人阅读的 `review.md`。ID区分书籍版本/章节或BV+P，不根据同名文件自动重绑。
- 长期区仅保存整理后的来源身份、指纹、原定位、笔记版本、内容清单、复核结论和未核项。不要复制完整转写、字幕、平台原始 `metadata.json`、音视频、原帧或凭据。
- 原材料继续放配置的 `raw_cache`，可以在记录中保存工作区相对的定位提示。迁移后提示指向的文件不存在时，显示“历史记录可读，原材料当前不可重新核验”。不要以历史哈希作为本次已读取的证据。

## 原材料保留与按需盘点

- 默认保留任务已取得的原书、来源音视频、实际用于整理的转写及人工校正稿；支撑复核的文本、截图、清单和记录也保留。有网页链接不证明将来仍可取得同一版本。
- 中间转换文件、重复副本只有在原件仍在、重建方法明确、且没有独立修改或复核价值时，才可列为清理候选。程序不凭文件类型、年龄或目录名判定可删；用途不明或未登记的材料暂时保留。
- 沿用现有存放位置，不为归档额外下载完整视频，不要求用户逐份登记或在每次入库重复确认。原材料不自动删除；实际清理另行明确文件范围。
- 按需运行 `scripts/cache_report.py --details`（可加 `--json`）：目录类别只是存放线索，报告只检查现有来源记录直接引用的文件，不扫描笔记正文。备份、试验及回滚产物单列，其中也可能保存原材料或唯一恢复依据。
- 未登记不等于未使用；哈希匹配只证明字节对应，不代表内容正确或完成了本次复核。缺失、变化、无法读取或越界时如实报告，不自动改记录或解除保留。
- 原材料未纳入当前知识树 GitHub 备份；长期来源记录已备份不等于原材料有异地副本。其他副本未核实前不声称仅有一份或已有备份。

## 更新顺序

1. 保留来源ID、题名、版本、原链接、源文本SHA-256及原页码/时间区间。无原文时不能伪造已执行的来源内容复核。
2. 先完成原材料→清单→笔记与笔记→原材料复核，再保留结构/登记结果和语义判断的区别。
3. 将简短长期入口追加或定点更新到来源笔记的来源说明，并保留 `<!-- source-evidence: SOURCE_ID -->` 回链标识。用户看到普通链接，不要求手填记录JSON。
4. 以最终笔记字节绑定长期记录与coverage。只追加长期入口时，记录 `reviewed_note_sha256` 与 `reviewed_prefix_bytes`，证明原稿前缀未变；如果编辑了正文，必须重新复核受影响内容，不能保留旧复核却只重算哈希。
5. 运行 `audit_source_evidence.py`。其结果只说明记录、笔记绑定和可用原文本的定位检查；未核内容、用户掌握及真实效果都不能因此升级。

已有缓存清单不删除。旧绝对路径保留在旧记录作为历史背景；新的采用记录使用稳定ID、原指纹和相对路径。只有明确选择的来源迁入长期区，不批量迁移所有历史报告。

## 记录格式

`record.json` 使用 `schema: source-evidence-v1`，包含：

- `source_id`：稳定ID；
- `source`：`kind`、`title`、`locator`、`text_sha256`、可选工作区相对 `local_text_hint`；
- `note`：Vault相对 `path` 与最终 `sha256`；仅追加入口时另保留已复核前缀的字节长度和哈希；
- `coverage`：既有v1登记格式，源文本哈希与笔记哈希对应上面两项；移存不复制原文大段quote；
- `review`：日期、实际复核范围、判断摘要、复核方式、未核项和限制；
- `migration`：如适用，保留先前清单指纹、工作区相对历史定位和本次更改范围。

`review.md` 提供简短的来源入口、笔记入口、已复核内容和未核项。记录与可读说明一起更新；审阅的是作者观点、识别文本还是实际声画，应明确写出。

## 只读检查

```powershell
python -B -X utf8 scripts/audit_source_evidence.py --config '<完整配置路径>' --strict --json
```

缺原文本或原文本指纹变化时，保留历史记录并说明不能重新核验/不能自动重绑。笔记字节变化、回链丢失、定位或记录格式无效则返回失败。日常与发布验证可以调用本命令，但 `content_reverified` 始终为false；有当前原文本时，另外运行原 `check_source_coverage.py` 并进行语义复核。
