# 准确性与融合规则

## 信息标签

- `[原材料 08:36]`：可直接回到视频或音频。
- `[第3章 P42]`：来自明确版本和页码。
- `[文章“空间关系”小节]`：来自网页小标题。
- `[OCR，待核对]`：扫描识别可能有误。
- `[ASR，待核对 08:36]`：语音识别可能有误。
- `[外部补充]`：不属于用户提供的原材料。
- `[我的理解]`：用户或整理者的推论。

不要给一般性概括塞满标签。关键事实、原话、数字、争议观点和容易误解的内容必须精确定位；一般总结可在章节末列来源。

## 默认目标与完成边界

默认来源笔记应让读者**完整理解实际取得的材料范围**：保留全部实质观点、关键论证、独特案例、方法关系、限定条件、反例与分歧。不能因为暂时看不出创作用途，就把材料中的独特知识提前删除。用户明确只要精选摘要或指定片段时，按该范围处理并明示边界。

来源正文先保留原材料，再按本次授权用途向所在分区的主题层提炼；学习材料不自动融合进创作区。摘要与目录负责快速进入，详细正文负责解释；主题笔记仍围绕创作问题精选综合。每段要点数、笔记字数、原子化程度都不是内容上限或质量指标，也不要求每段凑齐固定字段。

在现有“来源可靠性”或材料简介中分别说明：

- **材料获取范围**：实际取得的版本、章节/时间段、文字、音轨与图像；说明识别和访问限制。
- **笔记内容复核范围**：本次对照了哪些原材料范围，采用什么复核方式，有哪些已确认修正。局部复核不能写成全章、全书或全课通过。
- **尚未核实部分**：未看画面、未回听、损坏转写、缺页、未核数字或未取得原文等。

沿用现有 YAML 与 `完整程度`，无需批量迁移；该字段存在、目录齐全或 `沉淀状态: 已沉淀` 都不能证明内容保全。作者观点是否可靠、笔记是否忠实、用户是否理解、项目是否有效分别判断。

## 材料获取

先判断材料是否完整。遇到付费墙、缺页、音频损坏、无字幕、模糊扫描或访问限制时：

1. 明确缺失范围；
2. 告知能完成到什么程度；
3. 在工作更新中说明将使用外部资料补全，不需要再次等待确认；
4. 不把补充内容伪装成原材料。

视频先判断知识是否依赖图表、板书、构图对照、操作、剪辑或声音示范。“看这里”“这两个镜头”之类指代需要回到相应媒体；字幕/ASR只反映已识别语音。需要时使用所属平台允许的工具补看相关原帧、片段或音频，记录实际查看范围；只在配置的库外 `raw_cache` 保存原始产物。工具无法获取时保留缺口，不能靠常识、补充资料或重绘图声称看过原示范。抽看不等于全片视觉覆盖，时间码到结尾也不证明中间无缺失；语言识别置信度不等于转写准确率。

## 内容清单与写作

1. 在写来源正文前，按原材料顺序列出内容项及原定位：新观点、关键理由、独特案例、方法关系、条件、反例、分歧。一个完整论证可以作为一项，不能用一个宽泛标题遮住多个不同案例。
2. 清单由 AI 在库外维护，不要求用户填表或逐段确认。它是复核工具，不是预先正确的答案；原材料中未登记的内容仍需要检查。
3. 案例写出情境、关键过程/前后对照及它说明什么。保留作者用哪个观察支持哪个判断；方法保留何时选、谁作用于谁、怎样判断结果。不要用新增练习或普遍原则替换原案例。
4. 合并纯重复和不影响含义的口头赘述；可以压缩寒暄、广告和无知识增量的操作重复，但保留有独特作用的比喻、例外与不同结果，并在对应清单项解释合并理由。
5. 正文使用自然的段落、比较表或步骤。按阅读需要组织，不把后台逐项清单整份粘进笔记，不复制完整逐字稿。

不同材料的侧重：

- **文章/书籍**：保留论证次序、关键案例、图表含义；教材强调选择、处理与结果的关系。可省按钮重复，不能省必要对象关系或适用条件。PDF区别印刷页和页序；EPUB使用真实章节锚点。
- **访谈/播客**：保留谁在回答什么、谁提出异议、如何回应，以及个人回忆、预测与猜测的身份。不要把问答中的反驳整理成一致意见。
- **课程/视频**：把文字解释与原示范联系起来，保留教学中的常规方案、变体、取舍和失败对照；未看或未听的部分按证据范围标记。

## 双向复核与覆盖记录

写稿与复核分开执行；复核时重新读取原材料，不只检查笔记是否流畅：

1. **原材料 → 清单 → 笔记**：逐段检查新观点、论证、每个独特案例与限制是否有去处；尤其查清单本身漏掉的内容。反向再看被合并的信息是否改变理解。
2. **笔记 → 原材料**：检查具体主张、数字、因果、说话者和确定程度。专门找“可能变确定”“条件变普遍”“两个例子只剩一个”“作者观点混入整理者建议”。
3. **旧稿 → 新稿**：局部增补时保留原有独特案例、反例、来源、个人记录和无关内容；不能用整篇重写冲掉既有成果。
4. 修正已证实问题；对无法核清的内容标明待核与原因。若关键案例依赖不可得画面，只能完成其可核部分，不能以整理者另举例子代替缺失原证据。

覆盖清单和使用方法见 [覆盖检查接口](source-coverage-check.md)。运行只读 `scripts/check_source_coverage.py`，绑定原材料文本与最终笔记的 SHA-256，核对来源定位、笔记定位、处理结果和登记缺口。修改任一输入后重新核对受影响内容并更新记录，不能只刷新哈希掩盖过期审核。候选通过后若字节不变，仅切换到正式文件路径复验。采用的复核结论再按 [长期来源复核记录](durable-source-evidence.md) 保存到配置的长期区；不要把可迁移记录与原始缓存生命周期混为一谈。

程序检查定位、版本和登记闭合；`validate_note.py` 检查结构。两者都不判断语义忠实性，登记全行也不等于每行内全部知识保全。语义复核结论、实际范围与仍存缺口必须另行说明，不输出伪造的“知识完整率”。同模型第二遍称复核；额外代理只报告实际独立读取和评阅范围，不推定独立证实了全部内容。

交付前同时核对结构、覆盖记录与语义复核。存在待补/待核时可以交付有用的部分结果，但必须报告准确范围；仅把已核清的知识交给主题融合，不把缺口隐藏在“已整理/已沉淀”状态中。旧笔记没有新覆盖记录时仍兼容，不能据此自动认定已通过或启动全库改写。

## 多来源融合

1. 先分别提取每个来源的观点、论证、案例、方法和限制。
2. 再按知识问题融合，避免按来源机械拼接。
3. 删除纯重复，保留独特例子、不同定义和适用边界。
4. 冲突内容进入 `外部补充与分歧`，未解决时设置 `证据状态: 存在争议`。
5. 不用新材料覆盖用户已有的个人理解。
6. 普通增补可在归档确认后直接写入；删除、重大重排或冲突裁决必须先预览。

## 选择性核验

重点核验：

- 数据和日期；
- 历史事实；
- 人名、作品名和技术参数；
- 引用和原话出处；
- 可疑或相互矛盾的说法。

把创作者的经验、方法和审美判断标为作者观点，不假装它们具有唯一正确答案。
