# 知识库分区与归位

本文件是 stable Skills 共用的物理结构、入库去向和创作调用范围契约。路径从便携工作区 `.codex/knowledge-tree.json` 的共享加载器解析，不保存机器盘符。

## 当前结构

```text
{knowledge_library}/                         # 本工作区为个人影视知识树/知识库
├─ 00-待归档与知识地图/
│  ├─ 知识库主页.md
│  ├─ 我的知识树北极星.md
│  ├─ 知识树状态.md
│  └─ 专业索引/                               # 保留六类专业地图
├─ 创作区/                                   # creation_root
│  ├─ A-制片与协作/
│  ├─ B-故事与剧本/
│  ├─ C-导演与视觉/                           # C1、C2共同归C
│  ├─ D-声音与后期/
│  └─ 岗位共用/
│     └─ 项目经验/项目应用/
└─ 学习区/                                   # learning_root，同时是source_notes
   ├─ 课程/
   ├─ 书籍/
   ├─ 访谈与专题/
   ├─ 综合整理/
   └─ 个人思考/
```

沿用现有 A/B/C/D/E 岗位定义；有真实适合资料才创建岗位目录，不为 E 建空目录。跨岗位资料只有一个物理主归属，其他岗位通过导航引用；不复制正文。

六类专业名称继续作为 `分类`、`涉及分类` 和专业索引维度，不再决定物理文件夹。同分类／跨分类关系仍按这些属性判断；跨岗位或跨分区并不自动等于跨分类。

`knowledge_library` 是共同根，不等于全部内容获准用于创作。`source_notes` 是学习类普通来源的默认入库根，不是所有来源笔记的唯一合法位置；明确服务创作的专业来源可存入创作区对应岗位。`creation_root`、`learning_root` 为分区配置；未配置这两个字段的旧工作区继续使用已有布局，不静默补目录或迁移。

## 入库按目的选择

- 课程、个人阅读教材、访谈或学习专题默认进入学习区相应目录；跨来源学习总结留在学习区／综合整理。来源材料名或 YAML 中的 `课程` 字段不能单独决定用途。
- 明确为某岗位补充专业依据的资料进入创作区对应岗位；跨岗位的方法进入岗位共用，或按主要责任归位并保留导航。
- 学习材料可以完整整理、提炼方法并在学习区内部综合；这不自动授权融合到创作区。只有用户明确选定具体知识进入创作，才更新相应创作主题，保留指向原学习来源的追溯；不因此整篇搬走课程或清空个人内容。
- 本次结构迁移中，已混合课程／个人学习与专业补充的主题完整保留在学习区／综合整理，不拆正文。来源性质仍不清楚的少量材料也先归此处，之后按用户选定内容处理。
- 用户已明确目的、去向、架构或已授权本次范围时直接沿用，不重复确认；仅对真正会改变归位或笔记形态的缺项询问一次。
- `已沉淀主题`、`来源材料`、正式关系和个人记录继续表示既有事实；不因换目录自动升级、清空或改写。学习区未进入创作不构成入库未完成。

## 创作调用范围

默认先读取本岗与岗位共用，有必要再检查创作区其他岗位。C1/C2按C处理。目录只确定候选范围，不证明内容正确或适用。

学习区不参加默认创作调用。用户本次点名学习笔记时，使用 `--include-path <笔记路径>` 精确加入；多个文件逐项指定，不用目录或链接扩展授权。普通来源链接、专业索引、正式关系、回链和缓存命中均不授权自动读取学习正文。需要未点名的学习依据时明确缺口，而不是沿链接绕过边界。此次读取不改变笔记的长期归属，也不授权转入创作区。

上述限制针对创作回答。用户要求整理、学习或维护链接时，仍可在该任务已授权的精确范围内读写学习材料；健康检查的文件存在性结果不能被当作创作证据。

## 渐进整理与保护

1. 盘点实际文件、用途与来源，预览移动映射；明确批准的结构迁移按既定范围执行，不逐文件重复询问。
2. 保留完整正文、附件、个人记录和正式关系；同步受影响的路径与导航，不做未经授权的内容净化。
3. 普通知识整理不批量覆盖、移动或删除旧文件。项目资料未在本次整理范围时保留原位，以链接连接。
4. 在迁移完整性验证前保留原件和恢复依据；旧迁移基线不可为使新结构通过而重写。

## 主题过大时

当一篇主题笔记出现以下任一情况时，建议拆分并先征求用户同意：

- 超过约五个明显独立的子问题；
- 来源不断增加，内容导览难以扫描；
- 详细知识正文需要反复跳转；
- 既有复习区已经无法覆盖正文结构。

使用一篇地图笔记连接拆出的子主题，不按字数机械拆分。物理分区迁移本身不触发拆分。
