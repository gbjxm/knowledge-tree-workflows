# 影视知识连接契约

## 连接分层

不要把所有 wikilink 当成同一种关系。

1. **导航关系**：地图、总表、兼容入口指向主题。允许单向，不要求回链，不提升证据。
2. **语义关系**：两篇主题之间存在会改变创作判断的关系。必须双向记录关系、理由和依据。
3. **证据与应用关系**：来源证明主题、主题被项目调用、项目结果反馈主题。按来源与项目契约维护，不计入普通主题连接。

正式连接的单位是两篇已有且有实质内容的 `主题笔记`。关键词相似、分类地图、来源笔记、空主题和未写出的概念不是正式连接。

物理分区见[分区契约](../../grow-creative-library/references/library-layout.md)。同类／跨域以 `分类` 属性判断，不按岗位文件夹或学习／创作分区判断。保留已有跨区关系及来源追溯，不因搬迁重写关系含义；新建跨区关系仍需明确覆盖双方的授权。任何链接都不授予创作调用读取未点名学习正文的权限。

## 固定关系

| 关系 | 当前主题指向目标主题时表示 |
|---|---|
| 前置 | 目标知识必须先被理解或决定，否则当前方法无法可靠执行 |
| 转译 | 当前知识需要被转换成目标主题中的可执行表达 |
| 实现 | 目标知识是实现当前创作意图的具体手段 |
| 制约 | 目标知识限制、改变或排除当前方案中的选择 |
| 验证 | 目标知识或过程用于检查当前判断是否成立 |
| 反馈 | 目标产生的结果会反向修订当前结论、边界或方法 |
| 冲突 | 两边原则在特定条件下不能同时满足，需要显式权衡 |
| 互补 | 两边处理同一创作问题的不同必要维度，组合使用比单独使用完整 |
| 对照 | 两边容易混淆或代表不同路径，需要比较条件和代价后选择 |

反向关系必须单独判断，不机械复制同一个关系名。

## 固定依据

| 依据 | 使用条件 |
|---|---|
| 来源明示 | 可追溯材料明确讨论了两项知识的关系 |
| 现有笔记明示 | 当前知识库正文已经明确说明了该关系 |
| 多源综合 | 至少两个独立来源共同支持，差异已经保留 |
| Codex综合 | Codex 根据两篇现有主题作出的可解释推断 |
| 项目验证 | 项目应用记录了调用、结果和回写，能够观察到关系成立 |

`Codex综合`只表示连接假设，不得升级任一主题的证据状态。用户确认表示允许写入，不等于事实证据。

## 候选门槛

优先检查：

1. 用户明确点名的主题或创作问题。
2. 一篇主题正文已经讨论另一主题。
3. 两篇主题共享真实项目或相邻调用阶段，并存在清楚的创作传导关系。
4. 两篇核心命题之间存在可以说明创作后果的关系。

拒绝：只有关键词相同、只链接分类地图、目标为空、无法说明忽略关系会误判什么、为了连接率硬凑关系。

## 写回结构

同分类正式关系写入：

```markdown
### 同类知识连接

| 相关主题 | 分类 | 关系 | 连接理由 | 依据 |
|---|---|---|---|---|
| [[从梗概到可拍大纲]] | 故事与剧本 | 转译 | 把人物变化落到结构关节、选择与后果 | 现有笔记明示 |
```

跨分类关系继续写入：

```markdown
### 跨域连接

| 相关主题 | 分类 | 关系 | 连接理由 | 依据 |
|---|---|---|---|---|
| [[目标主题的实际Vault相对路径|场面调度与镜头覆盖]] | 导演与视听语言 | 转译 | 将人物选择转换为空间行动与可剪覆盖 | Codex综合 |
```

两种正式表格都必须与双方 `相关主题` 同步。表格理由描述具体创作后果，不复述标题。同分类关系不生成 `涉及分类`。

跨域关系使用可选属性：

```yaml
涉及分类:
  - 故事与剧本
  - 导演与视听语言
```

它必须包含本篇 `分类`，并与全部跨域表格行涉及的分类完全一致。没有跨域表格时不保留该字段。

## 确认与维护

- 首批既有主题关系先形成一份完整预览，用户一次确认后再整批双向写入。
- 首批语法确认后，普通高置信同分类连接可直接维护；低置信、冲突、删除和关系改义仍需预览确认。
- 新建、修改或删除跨域关系始终先预览确认。
- 静默、跳过或无关回复都不构成确认；未确认候选不写入 Inbox、Tasks 或隐藏队列。
- 导航链接允许单向；正式语义关系单边存在视为结构错误。

## 专题创建边界

本 Skill 永不创建主题。候选确实需要新专题时，先预览理由和所需内容，交给 `grow-creative-library` 创建有实质内容的主题，再返回本 Skill 建立正式连接。不得创建第五层或第七个分类。

## 完成、部分完成与停止

- **Done**：确认范围内的两端均写入，相关属性一致，笔记验证与严格关系审计通过。
- **Partial**：任一端写入或验证失败；报告已改变文件并恢复到操作前状态，不继续其他关系。
- **Stop**：候选未确认、目标无实质内容、依据不足、知识冲突待裁决或严格审计失败。不得报告完全完成。
