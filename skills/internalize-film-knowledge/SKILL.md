# Internalize Film Knowledge

帮助用户理解知识并用到具体问题中。根据当前请求选择讲解或检验；学习由用户主动发起，材料刚入库、存在历史待回答问题或缺少学习状态都不是自动启动的理由。

默认路径通过 `operate-personal-knowledge-tree` 的共享加载器读取便携 `.codex/knowledge-tree.json`。只有 `KNOWLEDGE_TREE_CONFIG` 可选择另一完整配置；显式 `--vault` 可覆盖，不回退到其他 Vault。

学习材料与创作知识的物理归位遵守[分区契约](../grow-creative-library/references/library-layout.md)。本次学习可围绕用户点名的任一区笔记展开；学过、回答或保存理解均不自动把学习知识转入创作区，也不扩大创作调用范围。

## 选择当前目标和回应方式

- 用户已选定材料或主题时，以该内容和当前困惑为准，按需读取原笔记及影响结论的依据。来源或主题没有学习栏目也可以正常讲解。
- “我没听懂”“我想理解”“这个为什么成立”等请求：直接解释机制，用相关例子或对照说明适用条件和边界。不要把求解释改成先答题；已知背景足够时不重复追问。
- “考考我”“检验一下掌握”等明确检验请求：进入一题检验。一般讨论、读过笔记或听过讲解不代表通过检验。
- “复习一下”按用户已给出的目标处理；没有测验意图时先帮助回顾和理解，只有缺少会改变方向的信息才问一个关键问题。
- 用户主动要求推荐学习内容、但没有指定对象时，才运行只读选题器：

```powershell
python .\scripts\select_review_target.py --json
```

选题器优先考虑北极星当前重点，再考虑未检验或较低掌握、较早检验日期。它不自动选择 `能迁移` 主题。缺少掌握字段按 `未检验` 理解，不补写字段或生成待办；长期疑问只作背景。

旧格式笔记也可只读讲解。仅当用户明确要求写回且实际需要兼容升级时，展示影响范围并按升级确认契约处理；不能为了继续对话要求用户先升级笔记。没有主题时直接使用来源内容，不创建空主题。

## 明确检验时：一题与诊断

判断回答前读取 [mastery-rubric.md](references/mastery-rubric.md)。根据已展示的掌握程度选择能说明真实差异的一题：

- `未检验`：用自己的话说明核心关系或机制。
- `能复述`：辨析边界、反例、失效条件或相邻概念。
- `能辨析`：在一个陌生作品或新情境中作出具体判断。
- `能迁移`：仅在用户主动要求继续检验时使用新案例。

可复用用户本次明确选择的来源中仍有意义的待回答问题；不要把历史队列当成必修清单。用户说“跳过”则停止检验，不改变状态。

提问后等待回答，不提前提供答案或评分；不在同一回合加第二题。收到回答后，依据其实际表现说明已抓住的关系、必要修正及理由，按需要用例子解释。反馈的篇幅和结构服务于困惑，不强制四行格式。

只评价已经展示的能力。部分回答保持最高充分展示的层级，不自动生成复习任务或继续追问。知识依据不足或有争议时，明确未决点并转交 `grow-creative-library` 核对，不能据薄弱证据判用户错误。审美偏好与创作取舍不当作事实错误。

## 默认仅对话，明确要求后才保存

讲解、回答检验和要求“继续”都不单独授权写回。没有明确保存本次内容的请求时，不修改笔记、学习状态、树状态或待办；也不先写状态再报告“未保存”。不在每次对话后自动追问是否保存。

已有的本次保存授权无需重复询问。写回前读取当前完整目标笔记，保留既有个人理解、疑问、默认做法、来源内容和其他工作成果。

- 只保存讨论所得理解：记录用户实际表达且要求保留的理解与疑问；不把助理的讲解冒充“我的理解”，不据此升级掌握状态。
- 保存检验结果：按 rubric 更新有真实回答依据的学习扩展，并追加简洁的日期、问题、核心回答与诊断记录；不粘贴整段聊天，不自动布置下一步任务。
- 来源笔记：仅在明确保存实际检验结果时更新 `理解状态`、`关键问题状态`；保留真实问题和必要诊断依据。此前没有 `## 关键问题` 时，一并保存本次实际题目以便回查；单纯保存讨论所得理解不添加问题或更新这些状态。没有主题时仍只写该来源。
- 主题笔记：按需新增可选的 `掌握状态` 和 `最近检验`，在 `## 我的理解、疑问与联想` 下复用或新增 `### 内化检验记录`；保留既有正文，不批量补字段。
- 不改来源主张、核心命题、证据状态、正式关系或无关正文。`能迁移` 是陌生情境中的能力证据，不等于真实项目的 `实践验证`。
- 只有用户明确采用某项练习或行动才保存为任务；不因回答不完整自动增加任务。

通过配置和 Obsidian 写入前置检查后，才执行授权写回；Obsidian 不可用时继续对话并说明保存尚未完成。每篇实际改动的笔记校验：

```powershell
python ..\grow-creative-library\scripts\validate_note.py "<note-path>"
```

保存完成后按需让 `operate-personal-knowledge-tree` 刷新相关状态，不生成全局下一步。来源提取、主题融合、正式关系分别由对应技能处理。

## 完成与未完成

- 讲解完成：回应了当前困惑、给出必要依据与条件，默认未写回。
- 检验回合：提出一题后等待；诊断回合：回应真实答案和必要修正，不自动追加问题。
- 授权保存完成：精确目标已写入并通过对应校验，说明保存位置；不把候选或校验失败说成已完成。
- 证据不足、用户跳过或保存受阻时，如实说明具体缺口，仍可继续不依赖该缺口的讲解；不虚构掌握或项目结果。
