# 按需核对原画面与转写

用于 ASR 可疑词、字幕识别疑点、图示或操作过程会影响理解的片段。沿用已确认的材料范围和笔记架构；不把每次入库变成固定的逐帧审查。

## 怎样选择依据

- 可下载字幕优先，但仍可能有错；接口不可访问和接口可访问但无字幕要区分。
- ASR 是待核对的识别结果。中文默认使用多语言 `base`；`.en` 模型只处理英语。语言检测概率不表示文字准确率，指定语言也不是检测成功。
- 句子明显不通、专名或论证关键处可疑时，定位原时间段，先复用已取得的原媒体。需要补画面时再取得相关片段。
- 硬字幕能证明“画面写了什么”，不能单独证明说话原音绝对正确。字幕与 ASR 不同时，标明依据；未实际听到的声音不写成已回听确认。
- 图示、演示、剪辑或表演承载知识时，读取相应原画面及前后变化。零散截图不能证明整段动作或全课已审看。

## 获取相关片段

从技能目录运行，时间均为原视频秒数：

```powershell
python .\scripts\bilibili_media_excerpt.py "https://www.bilibili.com/video/BV1eE411F73t?p=19" --start 798 --end 882 --frames "811,833"
```

这是示例范围，不是每次固定抽样的位置。依照当前疑点选择时间；省略 `--frames` 时生成少量未审看的预览图。

- 默认创建 `raw_cache/bilibili` 下的唯一目录；`--out` 只接受 `raw_cache` 内尚不存在且不经过目录链接的新目录。失败记录和原件保留。
- 复用公开元数据和播放信息，核对 BV/P/CID；通过 HTTP Range 取得索引及覆盖目标时间的媒体分片，再本地裁切。
- 产物包含无声视频 `video-excerpt.mp4`、预览图和 `excerpt.json`。签名播放地址只留在原始缓存响应，不能进入笔记或长期身份记录。
- 回执保存来源身份、请求范围、实际下载字节、解码结果、帧时间和哈希；`images_reviewed: false` 表示还需实际审看。不要靠改这个字段冒充审看。
- 当前支持最高 720p 的 AVC、连续 SegmentBase 和平面 SIDX v0/v1；其他布局、被忽略的 Range 或不完整响应明确失败，不自动下载整条视频。
- 需要现有 FFmpeg/ffprobe。缺少工具时报告缺口，不自动安装工具、OCR 或更大 ASR 模型。

## 判断能否使用

获取成功先核对实际时长、解码帧和错误输出，再打开相关图像。容器声明时长、HTTP 200、文件非空或进程退出码 0 都不能独立证明片段完整。

把核对结果保存在本次缓存：来源身份、原时间位置、实际看到或听到的内容、对转写的修正以及仍不确定的部分。保留原转写；用于整理的校正稿独立保存，不能以模型重跑替代人工证据。重要核对结论沿用共享来源契约，不新增一套笔记字段。

若只核对了几个词或几张图，结论只覆盖这些位置。其余部分仍保持 ASR、字幕或未审看的真实身份。缺口影响核心论证时，继续取得必要依据或将交付标为部分完成，不能凭语境补成教师原话。
