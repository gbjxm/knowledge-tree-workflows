# 创作区治理方案：服务小陌工作流六岗位

日期：2026-10-02。授权依据：小陌明确要求“先按照这样制定一个方案，然后执行”。

## 目标与采用的标准

创作区为当前 V1 工作流的 A/B/C1/C2/D/E 提供具体问题的专业判断依据。按“当前岗位与材料 → 必要问题 → 方法及条件 → 判断与完善”组织使用。六个专业分类继续作为属性与专业索引；C1/C2 保留 C 的共同物理与检索范围，分别提供任务入口。

1. 正文：围绕一个实际创作问题，保存原理、可执行方法、案例、反例、适用边界和来源身份。专业正文在默认创作范围内能支持常用判断。
2. 入口：说明何时进入、主要读什么、必要时转向哪篇、何时停止；以六岗位的问题和接口为轴。
3. 链接：区分方法入口、来源追溯、普通补读与既有正式关系。一份主要专业正文可以服务多个岗位；导航不制造新的正式关系，也不扩大学习区读取授权。
4. 验收：分别检查正文、实际读取与具体判断。结构通过、引用齐全和文字案例不表示真实影片有效。

## 执行范围与文件保护

本轮在已有 A/B/C/D/岗位共用骨架内治理全部现存专业问题。按内容审阅从综合整理的 36 篇主题形成对应创作正文：A 1、B 6、C 11、D 16、岗位共用 2；复用创作区现有 5 篇主题。派生正文与学习综合笔记对应同一批专业问题，不把文件增加解释为新增独立知识。

新正文采用区别于旧稿的文件名，记录“派生自”和用途。学习综合原稿保留全部已有内容，仅追加指向新创作正文的导航；不搬走课程、个人理解、疑问、练习和历史项目记录。课程正文、书籍、个人思考、项目记录、附件、北极星与既有正式关系保持原状。

新主题的正式“相关主题”初始为空；专业互补通过有说明的普通导航表达。继承的来源观点与本次岗位转译分别说明，不升级证据、成熟度、用户掌握或真实实践状态。时效性软件参数、权利与平台资格仍需实际使用时核对当前官方依据。

现有 14 篇创作来源汇编保留来源身份，追加指向新创作正文的入口；涉及来源属性的真实沉淀回链一起维护。其他学习原始来源继续通过旧综合主题及正文定位追溯。

## 执行顺序

1. 备份全部当前 Markdown 与配置、记录哈希，保存基线审计；三个专业批次在 Vault 外的候选区编写和复核。
2. 完整阅读原主题，提取专业内容、修正摘要与正文的边界冲突，生成逐篇对应清单。案例、反例和来源差异保留；本轮不重新提取媒体。
3. 整合候选，检查命名、链接、属性、来源身份与跨岗位接口；通过后写入创作区并追加学习综合/来源回链。
4. 重建首页和六岗位问题入口；同步专业索引和状态中的本轮事实，原有历史和全局待办保持。
5. 对每份改动笔记运行校验，运行严格知识库审计、正式关系审计、只读周复盘和 Daily 验证。
6. 用六岗位的具体问题执行快查及综合审查，核对命中正文、读取条件与实际判断；失败先定点修正本批正文或入口。没有真实影片与平台结果时只报告知识和文字调用验证。

## 交付与恢复

交付本方案、逐篇对应清单、六岗位入口、修改与验收报告及备份路径。证据保存在配置限定的 `.runtime/raw-cache/creative-governance/`，不写入全局行动表、不安装或同步 Skills、不修改工作流或任何项目。

恢复以逐文件备份和新增文件清单为准；只恢复本轮确实改动的文件，复核当前哈希后执行。旧迁移基线保持不可变。本轮未执行删除或外部上传。
