# 故障恢复

## 日常备份与指定版本恢复

目标由 `.codex/knowledge-tree.json` 的 `github_backup` 指定：私有仓库 `gbjxm/knowledge-tree-workflows`，分支 `main`。按需执行，不定时运行。以后说“备份知识树”即可使用这个范围。

```powershell
# 默认只读预览
.\scripts\backup.ps1
# 制作快照、推送，并从远端独立恢复验证
.\scripts\backup.ps1 -Apply
# 恢复指定版本到新的隔离目录，不修改远端
.\scripts\backup.ps1 -RestoreTest -Commit '<完整40位提交号>'
```

回执位于配置的 `raw_cache/github-backup/backup-<时间>/` 或 `restore-<时间>/`。`receipt.json` 中 `ok=true`、`verified=true` 才表示验证通过；普通备份还须有远端 `verified-backup-*` 标签。恢复文件位于回执的 `restore_path`，不混入 `.git` 和 Git 管理用的 `.gitattributes`。

在 GitHub Tags 页面可找到已验证版本。对应提交的 `manifest/package-files.json` 保存路径、大小、SHA-256 和目录清单，空目录也按它重建。新增、改写、删除均保存为新快照，历史仍在 Git 中；内容不变不重复提交。

## 本机工作区丢失后

需要 Python（含现有脚本依赖，如 PyYAML）、Git 和 GitHub CLI。先登录有权限的账号，凭据不写入配置。以下命令在新的空父目录运行，不能选正在使用的工作区：

```powershell
gh auth login
gh repo clone gbjxm/knowledge-tree-workflows knowledge-tree-recovery-tools
Set-Location -LiteralPath .\knowledge-tree-recovery-tools
git tag --list 'verified-backup-*'
git rev-parse '<选择的已验证标签>^{commit}'
.\scripts\backup.ps1 -RestoreTest -Commit '<上一行得到的完整40位提交号>'
```

恢复入口先验证工具克隆的文件清单，再重建 Git 不保存的目录。随后从远端另行克隆指定提交并导出到新恢复目录，核对字节、目录、配置、八个正式技能和依赖，运行 Release、Daily、知识库结构、正式关系、来源绑定及本地周检查。过程不注册或启动 Obsidian、不安装技能、不接入外部影视项目。

验证通过后，把恢复目录作为独立工作区审阅。真正替换原工作区时，另行明确目标路径：停止相关写入、保留当前目录、核对选定提交，再切换；不得直接覆盖仍在编辑的 Vault。安装技能或打开 Obsidian 按 README 执行，避免把同名历史 Vault 注册为活动仓库。

## 恢复范围

完整活动 Vault（笔记、附件、设置）、八个正式技能、脚本、统一配置、文档和长期来源记录随备份恢复。创作区、学习区、来源回链、个人理解、状态和正式关系保留原字节。

原始音视频、ASR/OCR 缓存、试验候选、开发备份、凭据、预览技能代码和外部影视工作流不在本批范围。缺原材料时可阅读笔记及历史复核结论、验证身份和笔记绑定；不能声称重新核对了原音频、视频或转写。重新核验须另行找回原材料。这一备份不覆盖整台电脑。

## 失败处理

- **源文件在快照期间变化**：本次不上传，等编辑稳定后重试；不锁住或修改笔记。
- **安全、体积或路径检查失败**：报告路径和原因，保留原件，不悄悄漏备。单文件达到 100 MiB 时停止，不自动引入 LFS。
- **上传失败**：保留本地快照和尝试的提交号。重试时核对远端，避免把连接错误当成远端完全没收到。
- **未知远端提交**：显示远端与本地已知版本，先比较改动；不强推、重置或自动合并，也不要删除状态文件绕过检查。
- **恢复或标签失败**：已推送版本保留，但不报告备份完成。查看 `restore-validation.json`、`receipt.json`，修复原因后再验证。
- **残留操作锁**：读取 `operation.lock` 中的进程号，确认备份进程已结束才移除该锁；保留运行目录和回执，不删除整个缓存。

验证只证明所列范围的完整性与运行兼容，不证明知识内容正确，也不替代 GitHub 账号的访问恢复。

## 日常检查、升级回滚与历史基线

```powershell
# 当前知识树检查；正常新增不要求等于旧迁移快照
.\scripts\verify.ps1
# 指定恢复载荷的字节、依赖和来源绑定检查
.\scripts\verify.ps1 -Mode Release -Root '<恢复目录>' -Manifest '<恢复目录>\manifest\package-files.json'
# 只在核对原始迁移时使用
.\scripts\verify.ps1 -Mode Migration
```

日常备份保存当前正式系统。升级回滚使用该次修改清单、原件和哈希，先检查后续编辑，仅恢复点名文件。`manifest/vault-before-migration.json` 是不可变历史基线，不能改写来让今天的增补通过。2026-07-18 的本机迁移前存档属于旧历史，不是今天最新的灾难恢复版本，不会自动并入备份。

配置存在多份候选时，用 `KNOWLEDGE_TREE_CONFIG` 指定唯一完整配置，不复制单字段路径。Obsidian 名称解析到另一条路径时停止 CLI 操作；隔离恢复只运行本地检查，不对关闭的历史仓库启动 Obsidian。

## 安装副本与正式技能不一致

运行 `.\scripts\verify.ps1 -Mode Installed`；需要时使用 `-TargetSkillsRoot` 明确目标，或用 `-SkillNames` 只检查点名的正式模块。报告会显示实际工作区、安装路径、缺失、内容差异、额外文件及必要依赖入口缺失。

返回码 `0` 表示比较范围一致，`1` 表示发现待核对差异，`2` 表示无法完成检查。安装目录不存在时只报告缺失，不创建目录；路径越界、目录链接或源目标重叠时停止，不跟随到其他位置。这个检查不会执行安装端代码或读其他技能正文。

差异不自动等于损坏。先核对修改记录，区分未同步的正式改动与本机定制；额外文件保持待判断。确需修复时保留原件，只同步点名范围，再检查一次。不得为得到“一致”而覆盖定制或批量删除文件。

## Skills 未安装

预览后按授权范围安装，保留无关本机定制，不恢复被排除的预览模块：

```powershell
.\scripts\install-skills.ps1 -TargetSkillsRoot '<Codex Skills目录>'
# 已获安装授权时增加 -Apply
```

不支持原生 Skills 的客户端直接读取 `skills/<name>/SKILL.md`。恢复检验本身不安装。
