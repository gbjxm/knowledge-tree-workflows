# 知识系统 V2.1

## 核心判断

来源笔记保存证据、语境和材料顺序；主题笔记保存可复用知识；用户主动请求的内化检验用于判断是否能复述、辨析和迁移，明确要求保存后才记录；项目应用记录知识是否真的有效；知识地图负责发现下一步。不要把“详细总结”误当成知识系统的终点。

## 四层结构

1. **来源层**：在首次确认并记住的架构下保存课程总览、课级或单集笔记、统一知识总结、书籍章节、访谈和文章。保留材料顺序、时间戳、页码、案例和可靠性边界。
2. **知识层**：围绕一个创作问题组织主题笔记，不按讲者或课程顺序复述。
3. **应用层**：把方法用于实际项目，记录条件、结果、失败原因和修订建议。
4. **导航层**：知识库主页、分类地图、Dataview 视图与 Tasks 队列。

## 为用户建立双轴，而不是通用百科

同一条知识至少有两个定位维度：

- **专业分类轴**回答“它属于什么”：故事与剧本、导演与视听、摄影美术、声音后期、创作实践、行业素材。
- **个人调用轴**回答“我何时需要它”：灵感与命题、故事骨架、剧本开发、视觉设计、资产与提示词、生成与镜头、剪辑与声音、复盘与方法升级。

物理归位遵守 [分区契约](library-layout.md)：创作区按岗位、学习区按学习材料组织。主题笔记用 `分类` 保留专业属性和索引，用 `适用阶段`、`解决问题`、`关联项目` 和 `横向能力` 支撑个人调用。知识库主页展示创作与学习入口、北极星、六类专业覆盖、已确认事项和证据缺口；历史学习记录仅作背景，不自动生成下一步。

先从用户 vault 中真实存在的项目、工作流、提示词、复盘习惯和卡点建立个人轴。不要假定一套抽象“标准工作流”就是用户的工作方式；新习惯出现时再调整阶段名称。

## 知识沉淀契约

新来源先确定入库目的与笔记架构；已有明确授权或架构直接复用。学习材料完成来源整理或学习区内部综合即可交付，不要求转入创作区。仅对本次已授权的知识融合执行以下沉淀检查，学习转创作须由用户选定具体知识：

1. 提取候选知识单元：`概念`、`原则`、`方法`、`案例`、`反例或边界`、`开放问题`。
2. 用“它解决哪个创作问题”命名候选主题，不直接用课程章节名。
3. 在本次归位范围内搜索现有主题的标题、别名、核心命题和相关知识，优先融合；不因存在跨区链接自动扩大范围。
4. 普通材料最多沉淀到 1-3 个主题；只有内容真正独立且足够丰富时才新建主题。
5. 写入主题时压缩来源叙述，保留可复用结论、步骤、适用条件、案例证据和冲突。
6. 建立双向链接：来源的 `已沉淀主题` 指向主题，主题的 `来源材料` 指回具体来源笔记。
7. 未写成内容的候选只放入 `待沉淀主题` 或 `#待沉淀` 任务，不创建空白 wikilink。
8. 沉淀完成后设置来源的 `沉淀状态`：`未沉淀`、`部分沉淀` 或 `已沉淀`。

## 主题笔记契约

一篇主题笔记回答一个可调用的创作问题，并包含：

- **解决问题**：用户在什么创作阶段、遇到什么情况时应打开这篇笔记。
- **核心命题**：当前最简洁、可操作的结论。
- **适用边界**：何时有效、何时可能失效、不能被误解为什么。
- **知识单元**：概念、原则、方法、案例、反例或待核验问题。
- **来源差异**：多来源之间的一致、补充和冲突。
- **项目应用与验证**：在哪个项目中如何调用、结果如何、需要怎样修订。
- **可选学习记录**：仅在用户明确要求保存学习结果后记录；不为知识入库生成复习区、自测题、练习或空个人栏目。

不要为了“原子笔记”过早拆分。满足以下任一条件再拆：

- 子问题被至少两个独立来源反复讨论；
- 子问题在不同项目中可以单独调用；
- 当前主题已经难以扫描，且拆分后关系仍能由地图清楚表达。

## 生命周期

来源材料可以保留以下既有学习扩展；默认入库不添加，缺失不代表知识未完成或用户已掌握：

- `理解状态`：`待理解`、`理解中`、`已理解`。
- `关键问题状态`：`待回答`、`已回答`、`不适用`。

重要材料完成来源整理和知识提炼后即可交付；不自动创建待答问题或等待个人学习。

`知识状态` 使用：

- `待提炼`：只有材料或摘录，尚无稳定结论。
- `已提炼`：已有明确命题、方法和来源。
- `已验证`：经第二来源交叉核验或实际项目验证。
- `已应用`：已在项目中调用并记录结果。
- `待修订`：出现冲突、失败案例或适用边界变化。

`成熟度` 使用：

- `种子`：单一来源或初次整理。
- `生长`：多来源融合，边界逐渐清楚。
- `稳定`：多次核验和应用，仍保留可修订性。

状态描述知识所处阶段，成熟度描述证据与使用积累；两者不要合并成一个字段。

`证据状态` 使用：

- `单一来源`：结论主要来自一个材料或同源材料。
- `多源互证`：至少两个独立来源支持，差异已经记录。
- `实践验证`：已经在真实项目或可观察练习中得到结果。
- `存在争议`：来源或实践互相冲突，尚未完成裁决。

`证据状态` 不替代 `知识状态` 和 `成熟度`。

`掌握状态` 使用：

- `未检验`：尚未脱离笔记解释；缺少掌握字段的 V2/V2.1 主题按此处理。
- `能复述`：能用自己的话说清核心关系。
- `能辨析`：能判断边界、反例或相近概念。
- `能迁移`：能正确用于一个陌生作品或新情境。

掌握状态按最近一次实际表现更新，可以上升或回落。`能迁移`不等于`实践验证`：前者检验个人理解，后者需要真实项目结果。仅在用户明确要求保存实际检验结果时补入`掌握状态`和`最近检验`，不要批量迁移旧笔记。

## 内化契约

1. 知识入库不自动启动内化；用户主动求理解、讨论、复习或检验时才交给 `internalize-film-knowledge`。
2. 求讲解时直接解释；明确求检验时按当前目标和真实表现选择至多一题，已有问题只在相关时复用。
3. 用户说`跳过`时不阻塞归档，也不改变理解或掌握状态。
4. 默认只在对话中交流；用户明确要求保存后，记录其真正表达的理解或检验结果，不覆盖来源观点、核心命题或已有个人理解，也不把讲解当作掌握证据。
5. 没有主题时只更新已授权的来源笔记；以后由用户选定知识及用途再融合，不创建空主题或自动跨区。
6. 材料本身证据不足时登记待核验问题，不把不确定结论当作用户错误。

## 链接规则

- 来源 → 主题：表示知识已经实际写入主题。
- 主题 → 来源：表示结论可追溯到材料。
- 主题 → 主题：普通提示可以在正文说明；会改变创作判断的正式关系必须交给 `weave-film-knowledge-connections`，不堆无语义链接。
- 主题 → 项目：表示知识被调用；项目必须记录结果。
- 地图 → 主题：表示导航归属，不替代正文中的语义关系。

优先链接具体笔记，不只链接课程文件夹或模糊名称。学习来源与创作主题可以保留跨区溯源；链接既不改变物理归属，也不授权创作调用自动读取学习正文。不要链接空文件，不要用标签代替有意义的关系说明。

正式主题关系统一交给 `weave-film-knowledge-connections`。同分类写入 `### 同类知识连接`，跨分类写入 `### 跨域连接`；双方分别判断方向，并同步 `相关主题`。关系固定为前置、转译、实现、制约、验证、反馈、冲突、互补或对照；依据必须区分来源明示、现有笔记明示、多源综合、Codex 综合和项目验证。Codex 综合不能提升证据状态。

`涉及分类`只服务已确认跨分类关系：有跨域表格时必须包含主题自身分类和表中全部分类；没有跨域表格时不创建该字段。同分类关系不得生成它。

只有一个独立创作问题横跨至少三个分类、连接至少两篇有内容主题、形成方法与边界，且不完全依赖 Codex 推断时，才在用户确认后由本 Skill 建立普通 `主题笔记` 形态的跨域专题；不新建顶层分类。专题有实质内容后，再由 `weave-film-knowledge-connections` 建立正式关系；Weave 永不创建主题。

## 项目反馈交接

项目应用的唯一权威模板、调用检索、显式反馈写回、幂等与事务回滚都属于 `apply-film-knowledge`。本 Skill 不创建或更新项目应用笔记，也不直接因为单次项目结果修改主题证据。

发现真实项目反馈时，向该 Skill 交接：

1. 项目与当前阶段；
2. 要解决的具体问题；
3. 调用了哪些主题和哪条方法；
4. 做了什么改动；
5. 结果为 `有效`、`部分有效`、`无效` 或 `待验证`；
6. 哪些条件影响结果；
7. 需要回写主题的结论、边界、反例或问题。

没有项目或没有可观察结果时，不虚构应用结论，也不自动创建个人练习；已有应用记录可以保持 `待验证`。

## 导航与维护

- 知识库主页按分区与岗位提供入口，显示北极星、专业覆盖、已确认事项和证据缺口；学习状态、旧复习任务仅作诊断，未请求学习时不形成学习行动。
- 六类地图位于控制目录的 `专业索引`，围绕专业问题组织真实入口；显示笔记所在分区，不让索引链接绕过创作读取范围。
- 每次处理新材料时顺手维护相关地图，不按日历批量重写旧库。
- `知识收尾`只检查本次变动主题，最多预览两组跨域候选；未确认候选不写入收件箱、任务或属性。
- 每次重大升级运行 `scripts/audit_knowledge_system.py`，检查空笔记、失效链接、V2/V2.1 属性、理解队列、掌握分布、证据状态和沉淀闭环。
- Excalidraw 只在关系复杂且图确实存在时链接；不要预先制造空图入口。
