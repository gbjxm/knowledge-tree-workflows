# 影视知识调用与反馈契约

## 主动审查

用户要求结合知识树检查当前材料时，完成单位是会影响本轮目标的判断，不是文章数量或模板字段。以下是判断路径；可合并已明确的事项，按证据需要深入，不要求每次生成整张表或固定数量的候选。

1. **定位当前材料**：确认目标、精确对象和版本、已知事实、用户报告的体验及尚待验证的假设。未给出的动作、时间方向、人物知情和因果条件保持未知；有帮助的变体明确标为候选。
2. **主动发现问题**：从材料与目标的差距发现需要检查的专业问题，包括未被用户点名但会改变当前判断的问题。常规岗位规则已足够的部分直接沿用；不要因存在知识类别就遍历全库。
3. **区分原因与反证**：说明哪项观察支持一种解释、什么证据会推翻它、还缺什么才能区分相近原因。问题有多种成因时比较有实际区别的分支；不把症状直接等同成因。
4. **寻找并核对依据**：知识树优先，按问题检索并读取方法、条件、案例或反例。若现有知识不足、互相冲突、需要原始出处或涉及现行规则，可按需外查原始来源；保留来源、核验范围和不确定性。无需为已授权的补证再次确认，但外查不授权入库。
5. **比较实际取舍**：把依据落到当前材料的具体选择，说明改善什么、可能损失什么、如何检验。原方案仍合理时可以不改；不为展示知识而强加动作、镜头、流程、审美或两套方案。建议不自动成为采用或执行。
6. **承接版本与反馈**：保存或复用当前事实与已完成判断的身份；反馈或材料变化后，只重开受影响的问题和依赖。新资料推翻依据时解释影响，不自动撤销既有项目采用；实践记录仍走明确授权的反馈写回。

当关键判断已有适用依据、主要替代解释能区分、剩余未知已明确时，结束本轮扩搜并交付。若缺的是实际素材、版本或决定性意图，给条件判断或只问那个决定性问题，不用更多理论填补。没有实质增量的重复阅读不作为完成条件。

## 调用范围与输入

物理边界见[分区契约](../../grow-creative-library/references/library-layout.md)。配置有 `creation_root` / `learning_root` 时，默认创作候选来自本岗与岗位共用；不足时可按问题检查创作区其他岗位。C1/C2统一视为C。来源和主题两种笔记均按实际所在分区判定，不以文件类型或 `课程` 字段替代用途。

用户本次点名学习笔记或课程目录后，用重复 `--include-path <准确文件或目录路径>` 加入本次范围。工具返回 `scope`，包含岗位、是否已跨岗、显式加入路径和实际读取路径；补读、`--read-id` 和续读须用 `--scope <返回scope的JSON>` 原样携带该范围，并携带 `--snapshot <原快照>`。复用scope时不同时追加路径或切换岗位；需要扩大范围就重新检索。未点名时不要读取整个学习目录，也不要从已有来源、正式关系、反链或缓存扩大到未点名文件。范围外的引用可记录为需补证入口，不能声称已读；没有分区字段的旧配置保持原兼容行为。

## 调用输入与模式

必填是具体问题。工作流同时传可确定的 `role`、`stage`、`task_type`、`object`、`constraints`、`expected_output`。

综合审查使用 `knowledge_review.py` 的 `--query` 表达任务目标，重复 `--question` 表达专业检查项，`--material` 提供必要材料摘录。任务类型、对象、限制和期望输出通过同名参数转交，作为 `context` 保留，不并入检索词或语义分母；不要把长剧本、岗位全文和权限描述塞进每条查询。

单一明确问题可用 `retrieve_knowledge.py` 快查。主题粗排依赖已有语义、受控别名和地图路由，在允许的创作范围内优先本岗与共用，再按需要跨岗；原相关性规则继续用于内容匹配，阶段仍是辅助。工具默认给出一张卡；关键依据不足时可补读必要章节、查互补主题或转综合审查，不以“一章”或“一篇”限制结论所需证据，也不默认通读全部候选。地图是导航，只有 `formal_relations` 可称为已确认正式关系。

`gap` 表示本次查询未获得可靠直接命中，不能据此断言全库没有相关知识。可以依据当前问题调整专业表述或阅读有明确理由的候选；仍无依据时如实保留缺口，不把最接近的无关主题当答案。

## 证据读取

`knowledge_review.py` 从当前允许范围内的主题和来源建立阅读包。按问题读取 `evidence_ids`，并核对 `support_ids`、`boundary_ids`；`alternative_ids` 是必要时的补读入口。这些标记只表示技术候选，不证明内容语义支持本次判断。

- `topic` 是主题综合，`source` 是来源笔记。实际读取须覆盖支撑判断的方法及不可分割的条件/反例，不能只读标题、引用表或“使用原则”便声称方法已覆盖。
- 表格拆出的 `table_row` 保留 `parent_id`；与其一起读取 `context_ids` 中的必要表头、单位、前提和限定。单行命中不授权忽略配套条件。
- 快查的 `method_chunks` 与 `reading` 分别说明方法片段及摘要/边界等字段是否截短；摘要不是完整原文。出现 `read_required` 时，将该项的 `continuation` 原样交给 `knowledge_review.py --config <配置> --read-request <JSON>`。工作流也可用 `retrieve_workflow_knowledge.py --read-request <JSON>`，不必再传 query/role/stage；不能同时更换范围或配置。
- 统一入口支持主题章节和来源证据，返回真实 `kind`，不把来源伪装成主题。首次从摘要补读时从正文开头读取，不把压缩摘要拼在原文前；后续严格使用新 `continuation` 的 offset，直到所需方法和条件完整。长段分页保留文件/快照身份与定位，原文变更后拒绝拼接旧页。只读本地笔记不等于核验了其外部原文。
- 原接口继续可用：`knowledge_review.py --config <配置> --read-id <证据ID> --snapshot <返回快照> --scope <返回scope的JSON>` 取得完整证据；`read_knowledge_section.py` 按唯一标题读主题或来源章节。重复标题须用准确证据 ID，不能凭同名标题猜位置。退出码0不表示全文已读；旧ID失效时重取受影响证据。
- `out_of_scope_links` 仅展示本次命中文档的相关导航，省略数量由 `out_of_scope_link_summary` 说明；它不扩张授权，也不代表范围外正文已读。导航先缩减，确需延后正文时仍保留证据身份及补读请求；`budget_exceeded` 如实报告无法在预算内交付的情况。
- 每个重要判断能反查到“当前材料观察 → 方法/条件 → 实际读取的段落及定位”。直接依据、跨来源综合、模型已有知识和本题推断应可区分；不要求给一般性过渡句逐句贴标签。
- `references` 中的URL和 `recorded_support` 是本地已有记录；真正访问原文后才能声称本次原文核验。整理日期不冒充原始发布日期。`source_gap: false`、链接存在或 `多源互证` 均不保证该段支持当前主张。
- 同一作者、同一手册的多页，以及主题、汇编和课程对同一观点的转述，不重复计作独立支持；独立性与该主张是否被支持分别判断。
- 软件版本、平台规则、价格、法律政策、比赛资格等时效事实以当前官方来源核验；不能只用静态笔记下现行结论。

复杂审查可用临时回执将 `facet_id` 对应到 `project_observation`、`judgment`、`reason`、`status`（applied/limited/conflict/gap/not_applicable）和 `evidence_ids`。这是可追溯工作记录，不是每次答复的固定格式。`--review-file` 与 `--application-file` 只检查引用和检查项机械完整；`traceability_pass` 不提升 `semantic_quality`，专业判断仍由阅读内容的执行者负责。

## 版本与复用

证据以当前源文件字节为准，派生索引和缓存不是事实源。修改、改名、撤回或删除会影响相关知识入口；旧阅读包的身份失效时重新获取受影响证据及必要依赖，保留未受影响的项目判断。

同一对象、材料版本、问题、知识证据和实施条件未变化时复用已有阅读，不为措辞返修重跑整轮。评测与复现须同时记录问题、知识文件、实际读取片段、相关脚本及其行为依赖、Skill/契约、配置和模型设置的精确身份；不能把一个语料 `snapshot` 当成整套运行身份。

快查派生索引位于统一配置的 Vault 外 `raw_cache/knowledge-retrieval/`，损坏时忽略并重建；`--no-cache` 应保留相同输入下的候选顺序。综合审查和增量补查按各自返回的快照核对；快照或检查点更新本身不表示语义问题解决。

## 四层验证

1. **正文**：关键主张充分、准确，并保留来源与适用边界；篇幅、标题和字段数量不是证据。
2. **读取**：当前问题选中的篇章和片段正确、足够，必要条件确实读到；有ID、链接或读取声明不足以单独证明。
3. **回答**：专业判断符合当前事实，说明原因与实际取舍；不得补造事实、收窄必要条件或把建议说成已完成。
4. **掌握与效果**：用户掌握根据其真实表现判断；真实项目效果依据可观察实践结果判断。二者分别记录，不由前三层或模型自检自动升级。

旧题和修复题用于回归。比较效果时可区分无库、当前自动调用、充分证据参照、候选自动调用；固定问题与版本，并避免同上下文和顺序泄露。单次高分、正文引用变多或一分之差不证明稳定改善。相关专业硬错误单列，不用总分抵消；只做与本次改动相关的验证。

## 证据状态与反馈写回

`单一来源` 保留核验需要；`多源互证` 不保证每条综合主张成立；`实践验证` 必须追到真实应用；`存在争议` 保留分歧与条件。缺证据显示“未标注”，缺掌握字段显示“未检验”，不得自动升级。

只有明确“记录、回写、沉淀这次实践”等动作授权才进入反馈模式。至少需要项目、问题与阶段、实际使用的主题和方法、实际改动、可观察结果及影响条件。无结果保持待验证；一次结果只能提出升级建议，不直接修改核心命题、方法、边界或证据状态。

使用唯一的项目应用模板。分区配置下，新项目应用默认进入 `creation_root/岗位共用/项目经验/项目应用`；旧配置保持原位置，不因一次反馈迁移旧记录。按已获授权范围预览精确改动，再准备全部目标文本和改前哈希，逐文件原子替换；任一写入或验证失败恢复全部触及文件并复核原哈希。稳定记录ID用于重复执行时更新原块，避免重复记录。已有对精确改动的确认不再重复索要。

工作流本机配置只保存知识树配置的显式路径、桥接启用状态及知识调用Skill名称，岗位Skill不复制Vault路径。知识调用、外部补证或缓存复用不授予 A/B/C/D/E 项目写入、媒体执行或知识树反馈权限。
