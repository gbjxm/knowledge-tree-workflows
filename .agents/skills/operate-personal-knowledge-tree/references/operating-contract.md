# 个人影视知识树 V2.1 运行契约

## 北极星

- 系统目的：让个人影视创作知识逐渐完整、可追溯、可理解、可调用、可修订。
- Codex 角色：知识导师与研究员，不替用户决定审美和个人目标。
- 当前重点：故事与剧本。
- 总体策略：故事与剧本近期优先，六个专业大类长期均衡。
- 默认形态：原理、方法、案例，同时保留边界和证据。
- AI 定位：通过 `横向能力: [AI影视]` 穿过六类，不建立第七类。

## 分区与四层结构

物理归位、目的判断和创作调用范围统一遵守 [分区契约](../../grow-creative-library/references/library-layout.md)。共同知识根下区分创作区和学习区；六类只作专业属性与控制目录下的专业索引。课程、书籍和个人学习默认留学习区，明确选定具体知识后才进入创作。

1. 来源层在首次确认的笔记架构下保存材料顺序、语境、时间戳、可靠性和完整程度；课程按真实课次、书籍按章节、系列按独立场次、单篇材料保持单篇。
2. 知识层按创作问题融合概念、原则、方法、案例、反例和开放问题。
3. 应用层记录知识被怎样调用、产生什么结果、需要怎样修订。
4. 导航层用分区与岗位入口、六类专业索引、状态及已有诊断视图展示内容和已确认事项，不自动安排学习。

正式主题关系由 `weave-film-knowledge-connections` 维护，不增加第五层或第七个专业分类。同分类使用 `### 同类知识连接`，跨分类使用 `### 跨域连接`；写入后必须有方向、关系类型、连接理由、依据和双向记录。导航入口允许单向。

## 六类专业属性与索引

| 分类 | 固定子域 |
|---|---|
| 故事与剧本 | 命题、人物、关系、情节因果、结构节奏、场景行动、对白、类型与改写 |
| 导演与视听语言 | 导演意图、场面调度、表演、视点、镜头、蒙太奇、视听节奏 |
| 摄影美术与现场制作 | 摄影、光线、构图与焦距、色彩、空间美术、服化道、连续性与现场执行 |
| 声音与后期 | 现场录音、对白、环境与音效、音乐、剪辑、调色与视效、混音交付 |
| 创作实践与项目复盘 | 开发流程、AI 提示词、资产版本、实验评估、失败模式、复盘与方法回写 |
| 行业观察与灵感素材 | 作品案例、创作者方法、技术工具、生产模式、平台发行、行业角色、现实观察 |

地图保存骨架和真实入口，不为尚未形成内容的子域创建空笔记。

## V2.1 属性

所有新建或大幅更新的笔记保留 V2 公共属性并使用 `知识库版本: 2.1`。

新建或实质更新的来源总览、单篇来源笔记和聚合笔记增加：

```yaml
笔记架构: 课程分层 / 系列分层 / 章节分层 / 单篇材料 / 主题直融
聚合单位: 课 / 章 / 集 / 单篇 / 主题
架构状态: 已确认
```

`架构状态: 已确认` 表示同一命名来源后续沿用当前结构，不重复询问；只有来源拓扑变化或用户改法时重新确认。`复习状态`、`理解状态`、`关键问题状态`及个人学习栏目均为可选；缺失不补写、不入学习队列。已有值继续校验：`理解状态` 只能是 `待理解`、`理解中`、`已理解`，`关键问题状态` 只能是 `待回答`、`已回答`、`不适用`。普通入库不新建关键问题或学习状态；历史课级的“不适用”和已有个人记录保持兼容。

主题笔记增加：

```yaml
证据状态: 单一来源
横向能力: []
```

`证据状态` 只能是 `单一来源`、`多源互证`、`实践验证`、`存在争议`。它不替代已有的 `知识状态` 和 `成熟度`。

`掌握状态` 只能是 `未检验`、`能复述`、`能辨析`、`能迁移`。它记录用户最近一次实际表现，可以上升或回落；`最近检验` 使用 `YYYY-MM-DD`。旧 V2/V2.1 主题缺少这两个字段时视为 `未检验`，只在用户明确要求保存实际检验结果时补齐，不因讲解或讨论自动写入，不批量迁移。已检验状态仍须有日期和对应记录。

主题存在已确认跨分类关系时才增加：

```yaml
涉及分类: [故事与剧本, 导演与视听语言]
```

它必须包含主题自己的 `分类` 并与正文 `### 跨域连接` 完全一致；没有跨域连接时不创建或保留空字段。同分类关系不得生成该字段。

## 内化接口

- `internalize-film-knowledge` 负责用户主动发起的讲解、讨论和理解检验，不负责采集、融合或证据核验。求解释直接讲解；明确请求测试才检验。
- 默认只在对话中进行，只有明确要求保存本次理解或检验结果，才写回个人记录或状态。讲解完成不代表用户已经掌握。
- `未检验`检验核心关系，`能复述`检验边界或反例，`能辨析`检验新案例迁移。
- 检验时每轮最多一题；`跳过`不改变状态，也不阻塞材料归档。
- `能迁移`可由陌生案例证明；真实项目效果仍由 `证据状态: 实践验证`管理。
- 获得保存授权后，没有主题笔记时只回写来源笔记，不为内化结果创建空主题。

## 理解与证据

- 材料先忠实保存与专业提炼，个人学习不作为入库或融合前置条件；来源证据不足与尚未学习分开判断。
- 不自动布置关键问题、自测或复习任务；课程原本的练习方法保留为来源知识。已有个人理解、疑问和学习记录继续保存。
- `单一来源` 说明结论尚需核验；`多源互证` 需要独立来源；`实践验证` 需要真实应用结果；冲突尚未解决时标为 `存在争议`。
- 外部补充使用独立章节，记录来源、日期、可靠性、补充内容、分歧和不确定性。

## 一次材料入库的沉淀顺序

1. 判断材料类型、目的、分区／岗位、笔记架构和专业分类；已明确或已授权的去向与架构直接沿用，真正缺失的决定一次确认。
2. 保存来源。
3. 根据本次目的提取候选知识单元；学习来源完整整理即可交付，需要时在学习区综合。
4. 仅在已授权融合的分区搜索现有主题；进入创作须用户明确选定具体知识。
5. 对授权融合写入最多一到三个真正有内容的主题，不为普通学习入库强建创作主题。
6. 为实际发生的融合建立来源与主题双向链接，保留学习原来源。
7. 设置有事实依据的沉淀和证据状态；不自动设置学习状态。
8. 完成材料入库。只有用户主动要求学习才交 `internalize-film-knowledge`；学习默认留在对话，明确要求保存才回写。
9. 由 `operate-personal-knowledge-tree` 更新相关地图和状态视图。
10. 到 `知识收尾` 时，由 `weave-film-knowledge-connections` 只检查本次变动主题并预览至多两组正式关系候选；未确认候选不进入 vault。

知识的实际调用和项目反馈统一交给 `apply-film-knowledge`。创作调用默认只读本岗与共用，必要时跨创作岗位；学习正文只经本次点名的 `--include-path` 加入，链接不扩张读取范围。只有用户明确要求记录实践或回写知识树时，才进入应用层写回。

## 周复盘的唯一行动

全局背景与当前任务分开。北极星仍是方向配置；全局待办只读 `知识树状态.md` 的两张表：`## 已确认的全局待办`、`## 待选择的全局事项`，列为“标识、事项、依据”。已确认表只放用户明确采用且尚未完成的全局事项；候选和历史记录不能晋升。缺表、重复标识或缺依据等解析错误必须显式报告，不伪装成无待办。

当前任务来自本次用户消息，优先于全局队列；可通过共享读取器的 `--current-task` 只读传入，不持久化。主页嵌入状态页的事实章节，启动上下文和周复盘调用同一 `read_state`；不独立保存一条“当前下一步”。

系统建议与已采用事项分开，最多一条，次序如下：

1. 显式确认与当前任务相关的阻塞；全库历史错误或分歧不因存在就自动抢占另一任务。
2. 来源不可读、越界、类型不符及已有状态记录损坏仍报告；缺少可选学习字段不算错误。历史学习状态只统计，不自动安排学习。
3. `learning_requested=False` 为共享读取器默认，仅本次显式 `--learning` 启用学习建议，参数不写入配置或全局待办。普通启动、入库、收尾和周复盘不调用选题器；单独传 `--source` 不启用。
4. 明确请求学习建议时，优先所选材料，已有待答问题只作未采用建议；没有登记问题则围绕材料讲解，不要求先补栏目，也不跳去其他主题。没有选定材料时再按北极星和掌握层级选题，或报告地图明示的实际缺口。
5. 地图“知识骨架”中明示为空白、待补、缺失或未覆盖的问题仍作诊断展示，按当前重点排序；不按篇数判断最弱，不为孤岛清零造关系。未请求学习时不把这些缺口转成学习任务。

任何系统建议都不构成采用或写回授权。多源互证、成熟度稳定、用户能迁移与项目实践验证分别需要自己的依据，互不代替。

## Hook 边界

Hook 只用于会话提示、改后检查和发现明显风险，不是可靠的写前审批门，也不构成用户确认。任何需要确认的关系、结构、删除或北极星变更，必须由执行 Skill 在写入前显式检查授权；Hook 缺失或未触发不能放宽边界。
