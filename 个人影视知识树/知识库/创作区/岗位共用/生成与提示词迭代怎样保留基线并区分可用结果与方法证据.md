# 生成与提示词迭代怎样保留基线并区分可用结果与方法证据

> 先分清本轮完成制作还是评估方法，冻结输入和判据、保留失败与选择理由；单变量帮助诊断，不足以证明全部因果。

## 调用入口

- 当前任务：制作完成后如何把提示词、失败、决策和结果沉淀为下一次可复用的方法。
- 先读适用边界，再根据症状选择知识单元、方法、案例与反例；不把所有方法当作必做流程。
- 本文可独立提供选定专业判断；原学习稿保存个人理解、默认做法、练习、项目计划和既有正式关系，来源链接只负责追溯。

## 核心命题

每次迭代只要留下五件事就能形成复利：当时要解决的问题、只改了什么、产出结果、为什么判断有效或无效、下一版模板或知识要更新什么。只保存“最后成功的提示词”会丢失因果，也无法知道它换项目后是否仍有效。

## 适用边界

- 适合：提示词、角色资产、镜头生成、剪辑、声音和整套项目流程的迭代。
- 不需要记录：没有影响判断的微小操作、无法复现且没有学习价值的偶然尝试。
- 常见误解：复盘不是写感想或归档全部参数，而是找出可保留、可删除、待验证的因果假设。

## 内容导览

### 整体脉络

- 先确定问题及适用条件，分清选用的理论模型与当前作品任务。
- 再按症状进入知识单元的概念、原则和方法，不机械填满检查表。
- 用完整案例和反例核对表面动作能否支撑因果、关系与证据判断。
- 对照专业接口、来源局限和验证办法，决定局部修改、回上游或保留未知。

### 详细导览

知识单元保留原专业细目；方法与案例进一步展开判断、贯穿例子和反证；外部补充说明同体系重复、独立局部支持及未验证范围。

## 知识单元

### 概念

- **最小复盘单元**：一个明确问题、一次主要改动、一份可观察结果和一个下一步判断。
- **基线版本**：原综合稿该轮用于比较的上一个提示词、镜头或剪辑版本。
- **回写**：把项目结果更新到主题结论、适用边界、反例或个人默认模板。

### 原则

- 一次尽量只验证一个主要问题，便于局部诊断；但单变量方法不能识别所有交互作用，多因素比较应明确设计与记录。
- 参数和提示词不是结论，输出差异与项目目标之间的关系才是结论。
- 没有真实使用证据的方法标为“待验证”，不提前固化成个人标准。
- 失败结果也应回写，因为它能缩小下次搜索空间。

### 方法

1. 写下当前问题与完成标准。
2. 记录基线版本和原综合稿该轮唯一主要改动。
3. 保存产出位置或关键截图，并按叙事、连续性、视觉、动作、声音和技术稳定性观察。
4. 标记结果：有效、部分有效、无效或待验证。
5. 写一句原因假设和下一步最小改动。
6. 回写对应知识主题或固定提示词模板，不把过程日志复制进所有笔记。

### 案例

原综合稿对《回家》历史材料的观察是：记录已含固定画质描述、焦距光圈、角色与场景参考、分秒动作和负面约束，但当时较少出现“哪一版产出怎样、哪条约束解决了什么问题”。这个例子说明，内容与参数保存齐全仍不等于结果对照完整。使用该方法时，可以从一次获授权的实际比较补齐对照链，不必追溯重写全部提示词；本轮未重新读取该项目或给它安排新任务。

### 反例、边界与开放问题

- 反例：每次生成都同时换模型、参考图、镜头运动、时长和文案，最后只保留最好的一条。
- 边界：不同模型版本可能导致旧经验失效，重要结论要记录模型与日期。
- 开放问题：成片质量需要一套多维但不繁琐的个人评价标准，后续可从真实项目复盘中形成。

## 方法与案例

### 找到可用结果与证明方法有效是两个目标

为当前镜头选出一条可用take，是制作决策；证明某段提示词能提高成功率，是方法评估。前者可以按创作需求选最好的结果，后者还要保留失败、抽样和选择过程。只展示最好的一条，会把筛选能力误当成生成方法稳定。

本库最小记录是“尝试了几条、按什么标准判定、各类失败是什么、最后为何采用”。不能把五条里一条成功写成稳定有效；也不应为了统计把当前制作强制拖入大量无必要生成。生产优先与方法验证分别标状态。

### 单变量便于定位，但不等于完整因果证明

[NIST实验设计说明](https://www.itl.nist.gov/div898/handbook/pri/section2/pri212.htm)指出，一次一个因素的方法会漏掉交互作用。本库构造：一个动作描述在参考图A上有效、在B上失效，可能是提示与参考的组合关系，不是动作描述本身“失效”。

若有这种迹象，可以在获准测试范围内比较两种描述×两种参考的四种组合，先固定其他关键条件，再考虑重复；不是每次都必须做完整实验。若同时换了模型、参考与镜头，仍可评价新方案整体可用性，但应把具体原因写成未拆分的假设，不说已证明哪一个词奏效。

### 基线与比较条件要先于结果保留

至少固定或记录模型／版本、输入资产、提示文本、时长、主要设置、评价规则和选择范围。Seed即使可用，也不保证跨模型版本、服务端更新和执行环境完全复现；应保存真实输出，不把“同Seed”当同一素材。

比较时尽量避免一边看结果一边改变通过标准；若确实因新发现修改标准，应保留旧标准并对同组结果重新评价。展示顺序、熟悉度和作者偏好都可能影响评分，重要判断可先隐藏方案标签；同一个模型换两个角色提示，不能自动称独立评审。

### 失败分类决定应该改什么

区分输入不完整、内容／因果不成立、表演／连续性问题、生成波动、技术格式错误和交接错误。同一输出可能有多类问题；先找会决定采用的关键缺陷，再决定修改哪一层，不默认都向提示词加形容词。

回写时把“本项目这一次有效”“在这些条件下多次有效”“仅提出原因假设”分开。明确的确定性错误可以一次举证后修正；概率性改进则需要可比结果与风险判断。记录授权不等于改Skill、模板或长期规则的授权，原综合稿该轮只补知识正文。

### 一次迭代的最小记录

| 字段 | 内容 |
|---|---|
| 问题 | 这次只解决什么？ |
| 基线 | 上一版或当前默认做法是什么？ |
| 改动 | 只改了哪个主要变量？ |
| 结果 | 画面或成片出现了什么可观察差异？ |
| 判断 | 有效、部分有效、无效还是待验证？ |
| 回写 | 哪篇知识、哪个模板或哪条项目决策要更新？ |
