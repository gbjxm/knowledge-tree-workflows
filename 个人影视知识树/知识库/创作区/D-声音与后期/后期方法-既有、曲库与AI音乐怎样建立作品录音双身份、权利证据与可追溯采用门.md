# 后期方法-既有、曲库与AI音乐怎样建立作品录音双身份、权利证据与可追溯采用门

> 本文是面向D岗位的专业方法正文。原稿的学习、个人理解与练习保留原位；此处以当前制作问题进入完整方法。旧稿中的阶段1—6、Stage、OPC及C部门标签用于解释专业功能与历史综合，不能替代当前V1的部门协作、工作集、采用或执行规则。

## 调用入口

- 当前问题：某条AI音乐服务允许商用，是否就能用于跨平台发布并登记为自己的Content ID参考？还需要分开核对哪些证据？
- 何时进入：已有、曲库、委约或AI音乐准备进入成片，需要确认来源、许可覆盖和采用证据时进入；不是用一个商用标签作结论。
- 先带哪些事实：当前对象和精确版本、已知创作意图、已经观察到的结果与限制；缺少真实媒体时区分方案判断和执行结论。
- 何时结束：关键方法及其条件已能支持本次判断，剩余未知已定位；不因章节多而要求通读全部，也不只读标题或摘要便宣称方法覆盖。

## 快速认识

- 核心问题：怎样证明当前CUT中实际使用的这个音乐版本，来自哪里、涉及谁的权利、许可覆盖什么，并且可以被追踪到原件、条款和人工决定。
- 主要结论：文件可得、平台可下载或AI服务允许商用，都只是证据链的一部分；正式采用必须同时通过四轴分流、Work／Master双身份、当前用途许可、来源追溯和用户批准。
- 调用价值：把创意候选与公开采用分开，提前暴露权利人不明、许可不可外推、AI参考输入无权和条款变化等阻塞。
- 适用环节：剧本与分镜中的歌曲／表演预判、Temp管理、既有与曲库选曲、AI音乐生成、音乐编辑、画面改版、可混音交付前的采用检查。

## 核心命题

音乐采用不是“文件检查”，而是同一实际使用版本的身份、权利和来源判断。

最低闭环是：

1. 用四条轴描述它，而不是只写“AI音乐”或“画内歌”。
2. 分别识别音乐作品与具体录音；没有使用原母带时也不能忽略作品层。
3. 把实际媒体、平台、地域、期限、场景、商业用途、宣传和允许编辑方式与许可逐项对应。
4. 对AI音乐另外核对服务合同、人类贡献、输入权利和输出第三方风险。
5. 保存原始文件、URL、合同／条款、版本、哈希、标识和派生过程。
6. 只有证据满足当前用途且用户批准，状态才可从候选推进到采用；其余继续标为Temp、待补证或停用。

Cue Sheet、ISWC／ISRC、C2PA、AI标识、Content ID结果和署名都能增加证据，但没有任何一项可以单独代替许可。

## 适用边界

- 本主题建立创作生产中的风险分流和证据门，不提供具体法律意见，也不替用户签约、付款、提交Cue Sheet或公开发布。
- `sync`、`master use`是常见行业语言，不是所有法域唯一的法定分类；中国项目仍需按真实权利、合同和用途核对。
- Source Music、Needle-drop、Production Music和Royalty-free的用法会随团队、曲库和地区变化，项目应先定义术语。
- 本主题不判断音乐是否好听、是否需要、入退是否成立；这些属于音乐叙事决策。
- 本主题不负责作曲、Mockup、Reconform、Music Master与Stems的制作质量；这里只保留它们与资产身份、许可范围和实际使用版本的接口。
- 当前没有选定真实曲目、AI服务、发布平台和地区，因此不能把任何音乐标为“已清权”或“无侵权风险”。
- 平台条款和AI服务条款会变化；真实采用时必须重读当前版本，旧快照只证明当时查到什么。

## 内容导览

### 整体脉络

- 分流：先用生产来源、叙事位置、制作状态和权利状态四轴说明对象。
- 身份：把Work与Master分开，确定当前实际使用的是作品、录音、歌词、表演、采样还是新录制。
- 许可：把合同或曲库条款逐项对应到平台、地域、期限、用途、场景、编辑和署名。
- AI：追加服务合同、人类贡献、输入权利和输出风险四问，并保存模型、任务和条款快照。
- 证据：用合同、原件、哈希、标识符、来源凭证、AI标识和派生记录组成可回查链。
- 状态门：未知不等于拒绝，但必须保持待核；只有当前用途证据充分且用户批准才进入正式采用。

## 知识单元

### 一、四条轴不能合成一个标签

| 轴 | 常见值 | 回答的问题 |
|---|---|---|
| 生产来源 | 既有录音、曲库、委约原创、重录、AI生成、混合制作 | 音乐怎样被获得或制作 |
| 叙事位置 | 故事世界内、故事外、由内转外、边界模糊 | 角色能否听见，观众怎样理解声源 |
| 制作状态 | Temp、参考、候选、修改中、采用、拒绝、待Conform、可交付 | 它在生产链的哪一步 |
| 权利状态 | 未核、待补证、许可受限、已核验当前用途、自有但合同待存 | 当前用途是否有证据支持 |

四轴可以任意组合：AI生成的歌可以是故事内表演，也可以只是Temp；既有商业录音可以成为故事外配乐；委约原创不因“原创”自动获得完整录音、表演和传播权利。

### 二、Source、Needle-drop、曲库、原创与AI描述不同问题

| 名称 | 本主题采用的工作定义 | 不能推出什么 |
|---|---|---|
| Source Music | 故事世界中有可推断声源的音乐，声源可见或不可见 | 不等于既有音乐，也不等于已清权 |
| Needle-drop | 把既有音乐或具体录音置入视听作品的常见说法 | 不说明画内／画外，也不说明许可已完成 |
| Production／Library Music | 为视听使用预制并通过曲库许可的音乐 | 不等于公版、无限平台、永久或免署名 |
| 委约原创 | 为当前项目创作或录制的音乐 | 不自动决定作品、录音、表演、署名和再利用归属 |
| AI生成 | 使用生成式模型获得全部或部分音乐 | 不自动意味着可商用、有排他版权、不侵权或可进Content ID |

一首资产可同时属于多个描述：委约原创歌曲可以是Source Music；AI生成的纹理可以与真人演奏形成混合Master；曲库录音可以作为Needle-drop进入画外配乐。

### 三、Work与Master是最低双身份

| 身份 | 典型内容 | 最少记录 |
|---|---|---|
| Work／音乐作品 | 旋律、和声、结构、歌词等作品层 | 曲名、作曲、作词、出版方、份额、ISWC／权利组织信息（如有） |
| Master／具体录音 | 某次具体演唱、演奏、制作和录制结果 | 录音版本、表演者、制作／录音方、厂牌／母带权利人、ISRC（如有） |

使用具体商业录音通常同时涉及两层。重录或Interpolation没有复制原Master时，仍需检查作品层；采样、Remix或Mashup可能同时涉及原录音和作品；歌词翻译、改词、重新编曲或敏感场景使用还可能增加改编与合同问题。

作品进入公版也不表示某个现代录音进入公版。反过来，拿到Master文件也不代表拥有其中的词曲作品。

### 四、既有音乐许可必须对应实际用途

采用前至少核对：

1. 当前使用的是作品、具体录音、歌词、采样、重录还是组合。
2. 谁拥有或代表Work与Master；共同作者和份额是否完整。
3. 许可覆盖哪个媒体／平台、地域、期限、商业用途、发行窗口和观众范围。
4. 是否只限片内使用，是否包含预告、广告、封面、片外传播或原声专辑。
5. 是否允许剪短、循环、变速、淡化、重混、改词、翻译或与特定画面结合。
6. 是否有署名、片尾、Cue Sheet、报告、费用或其他合同义务。
7. 新CUT后实际版本、时长、场景和使用方式是否仍与许可一致。

许可核对的是“这个版本在这个用途里能做什么”，不是判断一首歌抽象地“有没有版权”。

### 五、曲库降低搜索成本，不消除条款判断

曲库可能同时代理Work与Master，形成一站许可；也可能只覆盖部分权利、指定曲目或指定平台。`Royalty-free`通常描述某种收费方式，不能被解释成“没有版权”。

曲库采用应保存：

- 曲目页和下载来源；
- 曲库、曲目、套餐和账户主体；
- 购买／订阅日期、收据和许可证；
- 平台、地域、期限、项目数、商业使用和客户工作范围；
- 署名、Content ID、转授权、改编和导出限制；
- 条款版本或快照日期；
- 实际使用的录音版本与文件哈希。

“订阅时下载过”不能回答取消订阅后是否仍可用，也不能回答同一许可是否覆盖抖音、B站、电影节、客户广告和跨账号发布。

### 六、委约原创也需要证据链

委约原创至少区分：

- 谁创作作曲与歌词；
- 谁演唱、演奏、录制、制作和混音；
- Work、Master和表演相关权利由谁持有或许可；
- 使用媒体、地域、期限、宣传、改编、复用和原声发行范围；
- 费用、版税、署名、Cue Sheet和交付责任；
- 是否允许或要求使用AI，谁负责输入、模型、输出与来源记录。

“我付了制作费”不能代替书面约定；一人包办创作和录音时，也要把不同身份写清，避免未来无法说明谁能授权什么。

### 七、Cue Sheet记录使用，不授予许可

最终Music Cue Sheet通常记录节目、曲名、使用时长／类型、作者、出版方、份额和制作方，以支持识别、署名或版税分配。

它不等于：

- Work或Master的同步／使用许可；
- 改编、翻译、采样或宣传使用批准；
- 合同、付款、身份同意或AI输入授权；
- 阶段4用于创作、版本和批准的配乐Cue Matrix。

因此Cue Sheet字段可以从权利台账生成，但“已经填表”不得把`待核权`改成`已核验当前用途`。

### 八、平台许可不能向外推

平台曲库或商业音乐库的许可可能绑定：

- 平台与功能；
- 个人、创作者、企业或广告账户类型；
- 单条视频、单个频道或指定项目；
- 地域、期限、商业／非商业用途；
- 是否只能在平台内添加，而不能把带音乐母版导出到别处；
- 权利人撤回曲目后的静音、下架或收益变化。

平台没有拦截、没有Content ID Claim或允许上传，只能证明当前系统行为，不能证明独立许可链。准备跨平台时，应重新核对目标平台和原许可，不从一个平台的曲库名称推断另一个平台安全。

### 九、AI音乐必须回答四个不同问题

1. **服务合同**：当前服务、模型、账户套餐、生成时点和用途是否允许使用输出。
2. **人类贡献**：适用法域怎样判断Prompt、歌词、演奏、选择编排和实质修改中的人类表达。
3. **输入权利**：Prompt、歌词、参考音频、采样、声音模型和训练／微调素材是否有权使用。
4. **输出风险**：输出是否可能复制受保护表达、包含未清采样、冒用可识别声音／人格，或违反平台与发布规则。

四问不能合并成“可商用吗”。服务合同允许商业使用，只回答平台与用户之间的一部分；它不保证法定版权、排他性、第三方不侵权或所有平台接受。

### 十、AI音乐最小生成与权利记录

| 字段组 | 最小字段 |
|---|---|
| 服务身份 | 服务、模型、版本、账户套餐、账户主体、生成日期 |
| 任务身份 | 任务ID、Seed／参数（如有）、原始页面或API记录 |
| 创作输入 | Prompt、歌词、结构指令、参考音频、采样、声音模型 |
| 输入证据 | 每项输入的作者／提供者、来源、许可、身份同意和限制 |
| 原始输出 | 原始文件、文件名、格式、哈希、显式／隐式AI标识 |
| 人工贡献 | 选择、编排、演奏、重写、编辑、混音和替换了什么 |
| 派生血缘 | 父版本、DAW工程、Music Edit、导出版本和哈希 |
| 条款事实 | 条款URL、快照／检索日期、当时套餐权利和限制 |
| 风险与状态 | 相似性、声音身份、未清输入、平台限制、当前采用状态 |

如果使用可识别歌手声线或数字声音替身，必须另有针对具体人物、用途、项目和期限的身份同意记录；不能把姓名或声线当普通风格参数。

### 十一、标识符、C2PA和AI标识各自只证明一层

| 证据 | 能帮助什么 | 不能证明什么 |
|---|---|---|
| ISWC | 识别音乐作品 | 当前权利人、许可范围或已清权 |
| ISRC | 识别具体录音 | 作品层权利、当前母带授权或所有权不变 |
| C2PA／来源凭证 | 记录工具、输入Ingredient、生成和编辑历史，并检查声明是否被篡改 | 声明必然真实、版权成立、权利已清除或内容质量 |
| AI显式／隐式标识 | 满足特定服务和传播场景的来源提示、治理与机器识别 | Work／Master许可、人格同意或第三方不侵权 |
| 文件哈希 | 证明台账对应哪个文件实例 | 文件合法、内容原创或许可充分 |
| Cue Sheet | 记录节目实际音乐使用 | 授予同步、Master、改编或传播许可 |

保留现有标识和原件；若转码或平台导出会丢失元数据，应在旁车台账中保存原始标识、原件哈希和派生关系。不得把“没有C2PA”写成可疑，也不得把“有C2PA”写成安全。

### 十二、采用状态门

| 状态 | 含义 | 允许动作 |
|---|---|---|
| Temp／参考 | 制作中的临时用途标签，不自动豁免复制、传送或放映所需权利 | 先确认当前内部使用也有合法依据；保留替换计划，未经相应用途核验不进入公开包 |
| 候选 | 创作上可用，尚未完成证据检查或批准 | 可审听和补证，不得写Final |
| 待补证 | 已发现权利人、条款、输入或身份记录缺口 | 停止正式采用，补齐或替换 |
| 许可受限 | 有许可，但只覆盖特定平台、期限、地域或编辑方式 | 只在明确范围内使用；范围改变重新核对 |
| 已核验当前用途 | 证据与当前CUT、平台候选、地域、期限、场景和编辑方式一致 | 可提交用户作正式采用决定 |
| 采用 | 用户批准进入当前成片，版本与证据冻结并继续随变更复核 | 可进入可混音交付；不等于发布许可永远有效 |
| 拒绝／停用 | 创作、权利、身份或来源不满足 | 保留记录，不再作为当前事实源 |
| 被替代 | 新版本已成为当前使用对象 | 旧版本只作历史，不得误回连 |

`已核验当前用途`和`采用`必须分开：前者回答证据，后者回答用户的创作与风险决定。画面、平台、地域、期限、音乐编辑或条款发生实质变化时，重新进入核对。

### 十三、最小音乐资产与权利台账

| 字段组 | 最小字段 |
|---|---|
| 项目基线 | 项目、CUT、帧率、时码起点、平台／地域候选、台账版本 |
| Cue使用 | Cue ID、场景、TC In／Out、时长、画内／画外、叙事功能、Temp／Final |
| Work | 曲名、版本、作曲／作词、出版方、份额、ISWC／组织信息（如有） |
| Master | 表演者、录音版本、母带权利人／厂牌、ISRC（如有） |
| 来源原件 | 来源类型、提供者、原始URL、取得日期、原件与SHA-256 |
| 权利证据 | 合同／许可ID、许可方、平台、地域、期限、用途、允许编辑、署名与限制 |
| 编辑血缘 | 父版本、音乐编辑动作、DAW工程、派生文件和哈希 |
| AI专项 | 模型、版本、套餐、任务、Prompt／歌词、参考输入、同意、条款快照、AI标识 |
| 状态批准 | 缺失项、权利状态、Agent检查、用户批准、复核触发条件 |

OPC不必一开始实施完整权利数据库，但上述信息不能只存在于记忆、聊天记录或平台页面中。

## 方法与案例

### 授权链要问“谁能代表哪些权利”

Work／Master是最低识别模型，不是所有权利都只归两个主体。词曲可能有多位作者、多个出版代表，录音还涉及制作与表演等权利；现代编配、歌词翻译或采样也可能带来额外对象。作品层的描述并不意味着每个通用和弦、节奏型或风格都被某个人独占。

[WIPO独立电影指南的音乐部分](https://www.wipo.int/web-publications/rights-clearance-a-guide-for-independent-filmmakers/en/3-rights-assessed-during-clearance.html)提醒制作方确认实际用到什么、代表方能授权什么及发行范围。联系到一名作者不证明其仍持有全部授权权限；数据库和曲目页可以辅助寻源，但不是许可证本身。本库台账因此区分“查到身份”和“取得覆盖当前用途的授权证据”。

若许可证与素材的曲名相同，却指向另一录音版本、另一个客户或另一个项目，不能拿来补本条缺口。先核对合同对象与实际文件，再核对用途；证据有歧义时留待人工或专业法律审查，不由Agent推定授权链已成立。

### Creative Commons不只是署名要求

[CC官方FAQ的改编章节](https://creativecommons.org/faq/#when-is-my-use-considered-an-adaptation)明确：在CC许可体系中，把音乐按时间关系配到运动影像上视为改编。因而对BY-ND／BY-NC-ND音乐，“没有剪音乐、已署名”仍不足以据该许可公开分享配乐视频；需另外取得适当许可，或由专业人员判断是否存在适用的法定例外。这个结论是CC许可解释，不是宣称所有法域都用完全相同的改编定义。

同时看完整名称与版本：BY是署名，NC限制商业使用，SA约束改编作品后续许可，ND限制分享改编。是否商业使用不能只用“账号没开收益”作结论；SA音乐与其他受限素材是否兼容也要具体判断。CC0、作品已进入公版、平台提供的免费曲库不是同一个身份，不能用“免费”抹平区别。

使用本库分流时先保存准确许可、提供者、取得日期和实际用途；涉及客户广告、品牌合作、受限第三方元素或条款冲突时升级核验。署名清楚只是必要条件之一，不代替其他条件。

### 获准配视频与获准登记Content ID是两回事

[YouTube Content ID官方规则](https://support.google.com/youtube/answer/2605065?hl=en)对参考内容的排他权和可区分性有要求，列出第三方非排他许可、CC及公版等不适合作为参考的情形。买了使用许可，并不自动允许把整首库音乐作为自己排他控制的参考内容去识别、索赔其他人的视频。

这不等于“非独家音乐都不能用于视频”。本库分开四问：可以放入哪版影片，可以在哪些渠道传播，可以做何种编辑，能否用于平台权利管理参考。每问证据不同。没有Claim不代表取得许可，收到Claim也不直接证明违法；先保存通知、核对实际匹配区间及授权，再按平台程序和真实证据处理，不自动申诉或对别人发起主张。

### AI商业使用、可版权性与第三方风险分别判断

[美国版权局2025年Part 2发布公告](https://www.copyright.gov/newsnet/2025/1060.html)区分人类对表达的实质决定与仅提供提示词，也说明AI辅助不当然排除人的贡献获得保护。这是该机构对美国版权问题的观点和登记指导语境；本轮没有读取全部报告、裁判或中国法案例，不能据它判断每首AI音乐在所有地区都没有版权。

本库采用门因此不以一个标签给全曲盖章：服务合同可以允许商业使用，而某些机器生成部分是否受保护、人的歌词／演奏／编排是否独立受保护、输出是否使用第三方表达，仍是不同问题。保存人工改动的实际工程或版本差异，比只写“我做了很多Prompt”更能说明事实；但记录多也不自动证明法律上的原创性或排他性。

点名艺术家、可识别声线、相似旋律是需要具体核查的线索，不等于仅凭提示词就能认定侵权，也不能靠不写姓名保证无风险。没有选定服务和真实输出，本轮不判断套餐权利或音乐是否可发行。

### “内部Temp”与许可变化的时间边界

Temp只是制作状态，不是法律例外。内部复制、团队传送、客户试映、线上预览和公开发布可能有不同条件；不能把标了Temp当作允许任意下载与传播的依据。可以先用已有合法使用依据的参考，未知则保存链接、需求和替换计划，不擅自发出带音乐文件。

曲库订阅是否允许取消后继续使用、旧项目是否保留许可、何时算“创建／发布项目”、预告是否另需覆盖，取决于具体合同。后续网页条款改变，不自动证明旧许可被撤回；反过来，旧下载收据也不自动覆盖新项目。应保留生成／取得时证据，并核对当前用途触发了什么变化。本库只记录和分流，必要时请权利方或合格法律专业人员解释合同。

### 跨来源音乐采用法

1. 把当前音乐绑定唯一CUT、Cue、时长和实际文件。
2. 填生产来源、叙事位置、制作状态和权利状态四轴。
3. 识别Work与Master；说明当前是否还使用歌词、采样、表演或人物声线。
4. 根据来源进入既有、曲库、委约原创或AI专项检查。
5. 将实际用途逐项对应合同／许可，不只看营销页摘要。
6. 保存原件、URL、收据／合同、条款快照、哈希、标识和派生关系。
7. Agent列缺口，人确认权利证据、身份同意、审美和残余风险。
8. 只有证据通过且用户批准才标采用；CUT、平台、地域、期限或编辑变化时重新核对。

### 既有商业录音案例

剪辑使用某歌手正式发行录音作画外结尾曲。台账不能只写歌名：需要分别识别词曲作者／出版方和这个录音版本的表演者／母带权利人；再核对片内结尾、使用时长、目标平台、地域、期限、商业用途、片尾署名和是否允许剪短。若只找到出版方而Master权利人未知，它仍是创作候选，不是可公开Final。

### 曲库跨平台反例

创作者在某平台商业音乐库中选曲并完成视频，之后直接把带音乐文件上传另一平台。原平台能正常发布，只证明其平台内规则或当前系统行为；如果许可只限原平台，跨平台版本仍缺证。正确做法是保留无音乐母版，并为每个目标平台核对许可或替换音乐。

### AI歌曲案例

付费套餐生成一首带人声歌曲。除了保存最终WAV，还要保存生成时的模型、套餐、日期、任务ID、Prompt、自写／外来歌词、参考音频、声音身份、原始输出和条款快照；再记录人怎样重写、编排和编辑。若Prompt点名在世歌手、输出声线可识别或副歌疑似具体歌曲，状态应转待补证或替换，不能用“付费生成”直接批准。

### 公版曲与现代录音反例

一首古典作品的Work可能已进入公共领域，但某乐团近年演奏和录制的Master仍可能受保护。可以考虑自行演奏录制公版作品，却不能因为作品古老就随意复制现代录音。

### Cue Sheet冒充许可的反例

制作方完整填写曲名、作者、使用时长和Cue类型，却没有保存同步或Master使用许可。表格能帮助权利组织识别使用，不能反向证明制作方有权使用；状态仍应为待补证。

## 专业职责与工具边界

下表用于说明专业职责与创作取舍。已有采用方向和本次授权直接复用；普通专业步骤由岗位处理，新的重要创作取舍随完整候选统一审阅。每一行不构成独立审批门。

| 工作 | Agent可主做 | 用户／人工必须确认 |
|---|---|---|
| 四轴与Cue绑定 | 从CUT、时间码、文件和上下文生成初稿，检查状态冲突 | 当前权威CUT、音乐真实用途和最终叙事位置 |
| Work／Master寻源 | 搜索作者、出版方、表演者、厂牌、ISWC／ISRC候选并标缺口 | 权利人、份额和授权链最终成立 |
| 条款检查 | 抽取平台、地域、期限、商业、编辑、署名和撤回条件，对比条款版本 | 是否接受合同、费用、责任、限制和残余风险 |
| AI台账 | 保存模型、版本、套餐、任务、Prompt、输入、哈希、标识和条款快照 | 输入授权、声音身份同意、人类贡献和输出风险是否足够 |
| 相似性初筛 | 标记点名艺术家、具体作品、歌词、旋律、采样和声音身份风险 | 是否构成不可接受模仿、是否替换或寻求专业判断 |
| Cue Sheet草稿 | 从最终实际使用生成字段并找缺失 | 正式提交方、地区要求和最终使用事实 |
| 文件与派生 | 哈希、命名、版本对比、父子关系和缺失检测 | 哪个版本是采用原件，编辑是否在许可范围内 |
| 采用报告 | 汇总通过项、缺口、变化与停止条件 | 正式采用、许可执行、对外声明和发布 |

Agent未读取真实合同／条款、核对实际文件和完整听看上下文时，只能报告候选、缺口和风险，不能声称“已清权”“无侵权风险”或“可发布”。

## 小项目的适用范围

### 必须保留

1. 四轴和唯一CUT／Cue／文件绑定。
2. Work与Master双身份；未知即标待核。
3. Temp、候选、待补证、许可受限、已核验、采用和停用状态。
4. 当前媒体／平台、地域、期限、用途、编辑和署名与许可证据的对应。
5. 原件、合同／收据／条款快照、URL、版本和哈希。
6. AI服务、模型、套餐、生成时点、Prompt、输入授权、身份同意、原始输出、人工修改和标识。
7. Cue Sheet、标识符、C2PA、AI标识和Content ID结果不冒充许可。
8. CUT、平台、地域、期限、编辑或条款变化后的重新核对。
9. 用户的创作采用与残余风险确认。

### 按需启用

- 专职Music Supervisor、法务、出版与母带清权团队；
- 原声专辑、片外宣传、广告、跨地区发行和复杂窗口许可；
- 正式ISWC／ISRC注册、Cue Sheet提交和DDEX交换；
- 全自动C2PA签名、权利数据库和条款监控；
- 工会、表演者复用费、大型录音与多方份额管理。

按需不等于可以省略已经被项目触发的权利。使用商业录音、采样、翻唱、歌词改编、真实人物声线或准备公开发布时，相关检查必须升级；本主题仍只做到证据准备和停止判断，不执行许可或发布。
