# 场记与制作连续性怎样让跨镜、跨拍摄顺序和跨版本保持可追溯

> 本主题解决“镜头计划看起来能接，但实际拍摄后不知道哪个take发生了什么、补拍该恢复什么、D为什么不能选素材”的问题。场记不是只查水杯位置，而是维护剧本、表演、画面、资产、技术、进度与剪辑交接的现场事实。

## 快速认识

- 核心问题：怎样在非故事顺序、多镜头、多take和跨日制作中保存真实状态与差异。
- 主要结论：制作连续性至少需要场景底稿、逐镜/take记录和日终交接三件套；计划字段与实际发生必须分开，拍过不等于可用或覆盖完成。
- 学习价值：让导演能比较表演，摄影灯光能补拍匹配，生产设计能恢复状态，D能理解素材并识别欠拍。
- 适用环节：剧本定稿后、拍摄前连续性准备、每个setup与take、日终复盘、补拍及后期素材接收。

## 核心命题

制作连续性不是强迫所有镜头完全相同，而是保存“哪些必须相同、哪些可以变化、实际怎样变化、变化为何成立以及下游怎样处理”的证据。

```text
剧本和场景基准
→ 计划的开始/结束状态
→ 每个take实际发生
→ 与计划及其他take的差异
→ 可用性、覆盖与连续性判断
→ 日终交接和补拍条件
→ 剪辑采用与问题回传
```

最好的表演可能有连续性差异。专业处理不是自动弃用，也不是假装不存在，而是用记录判断能否改切点、用反应/插入覆盖、补拍匹配或承担差异换取表演收益。

## 适用边界

- 本主题处理实际拍摄记录，不替导演决定创作采用，不替剪辑师选最终表演，也不替各部门维护其详细专业方案。
- [[连续性剪辑与镜头衔接]]主要解决轴线、动作、视线、声音和状态怎样在成片中衔接；本主题解决现场实际发生了什么以及怎样被恢复和交接。
- 情绪连续性不能用“悲伤7、愤怒5”代替；应记录刺激、领会、行动、压制/泄露、决定和首尾状态。
- 角色可以由个人C合并承担，但记录功能不能由聊天记忆代替。
- 本主题不复制某个国家的全部纸质场记表，不涉及工会合同、工资或行政报表。
- 本主题先建立传统现场记录知识；未来任何数字或AI制作适配都应继承同样的事实与版本纪律。

## 内容导览

### 整体脉络

- `身份`｜用剧本版本、场号、story day、镜号、take和日期建立唯一坐标。
- `底稿`｜拍摄前固定人物、服化道、道具、空间、光线和不可改事实。
- `take记录`｜保存实际表演、动作、摄影、灯光、声音、问题和候选状态。
- `差异判断`｜区分有价值变化、可剪风险、技术问题和真正连续性错误。
- `覆盖与进度`｜记录已拍、欠拍、coverage owed和场景状态。
- `日终交接`｜把素材、记录、可用take、问题和次日条件交给导演与D。

### 详细导览

#### 三件套｜从基准到真实结果

主要讲什么：底稿保存预期状态，take表保存实际差异，日终交接把差异转成补拍和剪辑信息。  

关键内容：

- 三份记录共享同一场景、镜头、take和版本身份。
- 每个差异都记录“发生了什么、影响什么、是否接受”。
- coverage owed必须具体到缺什么功能，不只写“补镜头”。

复盘提示：素材离开现场后，D能否仅凭记录定位最可能的候选和已知风险。

#### 情绪连续性｜记录过程而不是强度分数

主要讲什么：人物的内部变化应转成可观察的刺激、注意、行动、呼吸、身体和决定阶段。  

关键内容：

- 记录镜头起止时人物“正处于哪一步”。
- 区分说话表演和聆听/反应表演。
- 有价值变化若难匹配，应留下证据供导演和剪辑选择。

复盘提示：两个镜头拼接时，人物是否像连续经历同一刺激，而不是突然换情绪。

## 知识单元

### 一、建立六级身份链

```text
剧本版本
→ 场号/场景身份
→ story day与剧情状态
→ 镜号/setup
→ take
→ 对应媒体文件与后期素材ID
```

这些信息用于关联不同记录，未必形成一对一层级；缺少必要对应会让“这是哪一个版本、拍的是什么、该和谁接”变成猜测。场记记录必须绑定真实媒体，而不是只留导演口头印象。

### 二、场景连续性底稿

| 维度 | 最小字段 |
|---|---|
| 剧本 | 版本、场号、页数、场景头、预计时长、对白/动作已确认改动 |
| 时间 | story day、日夜、与前后场时间距离、天气或时间层 |
| 人物 | 入场/离场、身体、关系、知情和情绪行动状态 |
| 表演 | 核心目标、关键刺激、不可丢反应、开场/结束行为阶段 |
| 服化妆 | 服装层级、穿法、发型、妆容、伤势、汗水、污损和湿度 |
| 道具 | 归属、数量、位置、朝向、功能、使用、损坏和消耗 |
| 空间 | 人物位置、轴线、屏幕方向、入口出口、可移动陈设和场景状态 |
| 摄影灯光 | 机位/构图基准、主光方向、综合色、曝光和允许微调 |
| 声音 | 同步/无声/wild/guide状态及会影响表演/剪辑的现场问题 |
| 风险 | 需要重复状态、不可恢复变化、天气/光线窗口与补拍条件 |

底稿记录采用基准，不把候选和废弃方案混入同一状态。

### 三、逐镜/take记录

| 模块 | 字段 |
|---|---|
| 身份 | 日期、场号、镜号/setup、板号、take、摄影机/素材ID |
| 覆盖 | 主镜/单人/双人/反应/插入/环境等功能与覆盖对象 |
| 表演 | 台词变化、抢话/停顿、关键刺激、聆听、行动、反应和首尾状态 |
| 动作 | 人物位置、朝向、视线、屏幕方向、道具动作和时序 |
| 摄影 | 机位、构图、运动、镜头/焦距、焦点、T档/光圈、滤镜、快门、FPS |
| 灯光及摄影接口 | 主光方向、实际灯和明显变化；EI/ISO、白平衡等向摄影确认，不混作灯具设置 |
| 声音 | 同步状态、wild/guide、噪声和技术问题 |
| 结果 | 完整/中断、候选/采用建议、NG原因、已知风险和需补内容 |

记录“导演喜欢”之外的具体原因：表演最好、反应完整、焦点失误、动作错、台词变、光线变化、声音问题或技术中断。

### 四、情绪与表演连续性

建议记录：

```text
刺激是什么
→ 人物是否已经接收
→ 当前理解/误解到哪一步
→ 正在执行什么行动
→ 反应被压制、泄露还是已经转成决定
→ 镜头结束时下一行动是否开始
```

还要记录呼吸、身体重心、注意对象、与对手距离、道具关系和显著台词节奏。不要把演员固定成必须逐帧复制；只标出剪辑需要的接口和真正会改变人物因果的差异。

### 五、状态差异的处理顺序

发现差异时依次判断：

1. 这是计划内的剧情变化，还是实际偏差？
2. 观众是否会注意；注意后是否改变空间、因果、人物或时空理解？
3. 差异是否来自更好的表演，值得保护？
4. 能否通过切点、反应、插入、声音或不同覆盖避开？
5. 是否需要补拍匹配、重拍或建立新基准？
6. 决定由谁采用，旧状态怎样标记？

场记提供事实和风险，不替导演/剪辑独自裁决创作收益。

### 六、coverage owed必须写功能

不要只写“还缺一个近景”。应写：

- 缺谁接收某个刺激的反应；
- 缺动作进入/完成/结果中的哪一段；
- 缺建立或恢复轴线、屏幕方向和人物位置的基准；
- 缺道具、信息、环境或时间变化的插入；
- 缺可隐藏技术/表演差异的剪辑接口；
- 缺哪个声音、wild line或环境连续元素；
- 当前已有镜头为什么不能替代。

这样补拍才能围绕剪辑功能，而不是机械扩充景别。

### 七、日终场记交接

| 内容 | 要回答的问题 |
|---|---|
| 今日完成 | 哪些场景、setup和状态真正完成，依据什么？ |
| 可用take | 候选是谁，表演/摄影/技术优点和风险是什么？ |
| 欠拍 | 哪个覆盖、反应、动作、状态或技术条件仍欠？ |
| 变更 | 剧本、台词、动作、调度、资产、灯光或摄影实际改变了什么？ |
| 连续性 | 次日/补拍必须恢复哪些人物、服化道、道具、空间和技术条件？ |
| 素材 | 媒体文件、素材ID、备份/检查和场记记录是否对应？ |
| D接口 | 编辑日志、标记剧本、连续性照片、问题说明和采用候选是否齐全？ |

“已拍”只证明相机运行过；完成需要覆盖、素材、记录和问题状态都清楚。

### 八、场记三件套

1. **场景连续性底稿**：开拍前的采用基准和不可改事实。
2. **逐镜/take记录**：现场真实发生、差异、候选和问题。
3. **日终场记交接**：完成、欠拍、次日恢复条件及D编辑信息。

三件套应共享字段标识，避免同一人物状态在三张表中使用不同名称。

### 九、常见失败

1. 只记录水杯和衣服，不记录刺激、行动和反应。
2. 把镜头计划复制成场记表，没有记录实际take差异。
3. 缺剧本版本、story day或镜头/take身份。
4. 所有take只写“好/不好”，没有具体原因。
5. 情绪连续性使用强度数字，却不知道人物在回应什么。
6. 为匹配动作牺牲最好表演，又没有比较剪辑替代方案。
7. 只写“缺近景”，不写覆盖功能和已有镜头为何不足。
8. 变更没有同步给服化道、摄影、灯光和D。
9. 连续性照片没有场景、镜头、take、时间或对象说明。
10. 素材文件与现场记录分离，后期无法确认对应关系。
11. 把“拍过”写成“完成”，未记录中断、焦点、声音和覆盖问题。
12. 依赖聊天记忆，补拍时无法恢复真实状态。

## 从场记字段到剪辑能用的证据

依据[ScreenSkills制定的英国职业标准SKSC32](https://www.ukstandards.org.uk/en/nos-finder/SKSC32/monitor-script-coverage,-continuity-and-technical-camera-details-during-shooting)与Screen Ireland的场记职业框架（印刷页4—7）。具体记录格式按团队约定；下面的分层例子为本库综合。

### 身份链是关联关系，不是一对一文件树

**Slate（板号/场记板标识）**、**Setup（拍摄设置）**、**Take（拍摄遍次）**和文件名可能按不同规则组织。一个take可以对应A/B摄影机、独立录音的多个文件；一段长记录也可能包含多次局部尝试。应记录机身/卷号/片段名/录音标识及同步线索，不靠相同文件名猜对应。

**Timecode（时间码）**是定位和同步线索之一，必须核对时基、是否正确同步及实际内容；数值相同不证明两文件拍的是同一事件。对没有拍板、尾板、无同期声或局部接拍的情形，保留说明和已知关联，不补造不存在的拍板事实。

### 划线剧本、逐条日志与场记照片各解决什么

**Lined Script（划线剧本）**把拍摄覆盖与剧本位置相联系，回答哪些段落被哪些设置覆盖；**Editor’s Log（剪辑日志）**记录每条的描述、偏好和问题；照片记录某个时刻的外观与摆放。线条画满不等于对白清楚、关键反应完整或每条都能剪；照片也不能证明动作时序和持续状态。

团队应先约定线条、画外动作、接拍和多机位的标法，不能由一个教程符号推定全球标准。交给剪辑的是覆盖索引加可定位的媒体事实，而不是“全拍完了”的抽象声明。

### 把观察、判断与决定分栏

| 性质 | 合格写法 | 不应替代为 |
|---|---|---|
| 观察 | B机take3在人物抬头处失焦；A机该段未见同类问题 | 本条全坏/全好 |
| 专业判断 | B机近景可能损失领会瞬间，需查其他覆盖 | 已证明无法剪辑 |
| 创作偏好 | 导演偏好take3的停顿，但保留已知焦点风险 | take3全段及所有机位已最终采用 |
| 未观察 | 未听独立录音，只听现场返送 | 声音已验收 |

**Circled Take（圈选遍次）**通常记录现场偏好，具体含义按团队约定；不是母版采用或技术全项通过。可用性还可限定到一段或一种用途，不能让一个状态标签抹去内部差异。

### 接拍要恢复过程，不只恢复最后姿势

**Pick-up（接拍/局部补拍）**从场景或动作的一部分重新拍摄。需记起始台词/动作、人物已知信息、持物、刺激和节奏，预留足够上下文与重叠动作供剪辑判断；并非固定“前后两秒”就够。上条台词相同但领会阶段不同，也可能难接。

同一杯子左手换右手不必然废弃：先记录何时发生、画面是否可见、是否影响结果，并把风险交给导演与剪辑。记录应保留差异，不替剪辑用想象中的反应镜掩盖。

### 拍摄时长不能直接相加为成片时长

开机总时长包括拍板、准备、重复、停顿、失败和重叠覆盖；场景估计时长则按故事/表演运行估计，成片时长还取决于实际选剪。三者用途不同。计时时写测量的起止事件、是否含拍板和准备、是完整场景还是pick-up，不把多机位同一事件重复计入预计片长。
