# 影视成片怎样把画面、声音、字幕与图文汇合为版本冻结、QC通过且可恢复的母版

> 本主题研究阶段1—5的专业产物怎样真正汇合成一版可证明的作品。它不把“导出成功”当作完成，而是先用唯一CUT和离线参考核对Online回原，再冻结PIC、AUD、TEXT、GFX组件，建立MASTER-COMPOSITION，生成并回读母版候选，用自动技术检查和OPC两遍完整审看关闭问题，最后冻结版本、保存Manifest与恢复包，再把唯一媒体对象和哈希交给E。

## 快速认识

- 核心问题：为什么一个文件能够播放、自动QC通过、哈希也正确，却仍可能使用旧CUT、错Grade、错Printmaster、错语言字幕或旧图文。
- 主要结论：成片不是“目录中最新的几个文件”，而是一个明确Composition对精确组件版本的绑定；母版通过也必须绑定实际输出文件、QC证据和批准状态。
- 学习价值：把最终导出升级为可核对、可回归、可冻结、可派生和可恢复的完成系统，避免final_final命名、静默换版和只存播放文件。
- 适用环节：Picture Lock后的Online完成、Final VFX／Grade／GFX汇入、Printmaster和Timed Text接收、母版输出、最终QC、归档及向E发行交接。

## 核心命题

专业成片完成需要连续回答六个问题：

1. 各专业交付的精确组件是谁；
2. 哪些组件共同构成当前作品版本；
3. 哪个实际输出是D内部权威母版；
4. 哪个精确哈希经过了哪些自动与人工检查；
5. 修复后哪些范围必须重新验证；
6. 未来能否重开工程、重连媒体并再输出。

~~~text
唯一CUT／Picture Lock＋离线参考
→ Online回原与逐项比较
→ Final VFX／Grade／GFX／Printmaster／Timed Text组件冻结
→ MASTER-COMPOSITION
→ 内部AV-MASTER候选
→ 实际输出回读
→ 自动技术QC
→ 人工第一遍：观众体验
→ 人工第二遍：技术与组件关系
→ 问题路由、修复与影响半径回归
→ 母版版本冻结＋Manifest／Hash
→ RESTORE-PACKAGE与恢复测试
→ 向E交付唯一对象、哈希与限制
~~~

最大的盲点是把“文件完整”误当成“作品正确”。哈希只能证明当前字节与记录一致；若Composition一开始引用了错误声音、字幕或画面，错误文件的哈希仍然可以完全正确。

## 适用边界

- 本主题处理阶段6的Online汇合、母版角色、最终QC、版本冻结、恢复与D／E交接，不指定剪辑、调色、混音、字幕、转码或资产管理软件。
- Picture Lock是获批准的剪辑时值与结构基线，不表示Final VFX、Grade、GFX、声音和字幕都已经完成；锁画后变化仍需受控解锁、Reconform和新版本。
- 字幕文本、翻译、SDH、Forced Narrative、片头片尾、终混审美、响度、声道与M&E的内部制作方法属于相邻主题；本主题只检查它们以哪个最终组件进入Composition。
- Stage5拥有色彩解释、监看、创作Look和色彩专项QC；Stage6只做汇合、图文／编码后的颜色回归，不重新发明Look。
- Textless、Clean Plate和口语中的clean master只作为交付接口。它们没有跨平台统一范围，必须写清移除与保留了哪些文字、图形、字幕、台标或品牌元素。
- 本主题不规定统一容器、编码、分辨率、帧率、响度、True Peak、声道、Timed Text格式、Hash算法、备份份数或保存周期；真实接收Profile优先。
- 内部母版、交付母版、Mezzanine、发布派生和保存母版是功能角色，不必一一对应不同物理文件，但同一文件承担多角色时必须显式记录。
- 阶段6可以制作内部母版和已获明确技术目标的派生物；标题、文案、封面、平台选择、上传、发布回执和发布后复盘属于E。
- 当前尚未对用户真实AI短片执行Online回原、两遍整片审看、平台转码比较或完整恢复测试，因此不能声称任何真实项目母版或恢复已经通过。
- Agent未读取精确媒体、未运行实际检查、未看到用户对同一哈希完整观看与核听的证据时，不得宣布母版、QC或恢复通过。

- 时间基线｜从唯一CUT、Picture Lock和离线参考开始，先证明Online时间线使用正确原件并复现剪辑决定。

## 知识单元

### 一、唯一CUT与Picture Lock是时间基线，不是最终母版

Stage6接收的最低基线包括：

- CUT ID、Picture Lock批准状态与批准日期；
- 帧率／时间基、起始时间码、总时长和画幅；
- 带烧录时间码、镜头或源名的离线参考；
- 编辑结构或可交换时间线；
- 锁画后Change List、Reconform记录和最新批准人；
- 尚未完成、临时或有意保留的效果清单。

Picture Lock只说明剪辑结构当前获准成为各分支共同依据。Final VFX、Grade、图文、终混和字幕可以随后完成；任何影响镜头顺序、切点、时长或对白事实的变化，都必须建立新CUT并传播到所有受影响组件。

### 二、Online Conform必须回原并与离线参考比较

Online回原不是“所有媒体重新上线”这一项状态，而是逐项证明高质量时间线仍是被批准的作品：

1. 以素材身份、生成批次、时间码、首尾画面和时长确认代理与原件父子关系；
2. 核对每个剪切、转场、变速、定格、缩放、裁切、重定位、稳定和嵌套效果；
3. 替换Final VFX并确认镜头版本、Handles、画幅和Alpha；
4. 接收Stage5 Grade／Output时确认没有重复Input、Look或Output Transform；
5. 汇入最终图文时核对文本、位置、透明边缘和色彩空间；
6. 与离线参考正常速度比较，再对差异点逐帧确认；
7. 把未解决的低质量素材、临时效果和有意差异写入开放问题。

“媒体在线”和“画面看起来相似”都不能证明Conform正确。代理可能带有Baked Look，原件也可能因重生成、错批次或错解释而静默换义。

### 三、PIC、AUD、TEXT与GFX是四类组件角色

| 组件 | 最低内容 | 冻结前必须回答 |
|---|---|---|
| PIC | Final VFX、Online完成、Stage5批准Grade／Output和画幅 | 对应哪个CUT、色彩目标与参考，是否通过色彩专项QC |
| AUD | 特定语言／布局的Printmaster | 对应哪个CUT、起点、时长、声道、Profile和声音QC |
| TEXT | 某语言、某类型的Timed Text或明确不适用 | 依据哪个最终音频、是否人工校对、时序和用途为何 |
| GFX | 片头片尾、屏幕文字、标题卡、Texted／Textless接口 | 文本是否批准、字体／资产是否可恢复、在哪个色彩链合成 |

组件是逻辑角色，不必等于四个单独文件。烧录字幕会进入GFX或PIC像素，但仍应保留可编辑TEXT源；图文已烘焙进PIC时，Manifest要记录对应GFX版本，而不是让它消失在“最终画面”里。

### 四、组件身份先于组合

每个组件至少记录：

| 字段 | 作用 |
|---|---|
| Object ID／角色 | 避免靠文件名猜用途 |
| Parent／来源版本 | 追溯从哪个CUT、工程或组件产生 |
| CUT／时间事实 | 核对帧率、起点、时长和同步 |
| 路径／文件事实／哈希 | 定位精确实例并验证字节 |
| 语言／声道／字幕或图文类型 | 区分版本含义 |
| 色彩／声音／文本／编码Profile | 说明怎样解释和检查 |
| 状态 | Approved、Changes Requested、Hold或Superseded |
| 限制／未检查项 | 防止“通过”掩盖未知范围 |

组合不能动态引用“文件夹最新文件”。只有身份、状态和限制明确的组件才能进入当前MASTER-COMPOSITION。

### 五、MASTER-COMPOSITION冻结“这版作品由什么组成”

MASTER-COMPOSITION不是媒体编码，而是一条批准关系。OPC最小字段：

| 字段 | 最低记录 |
|---|---|
| Composition ID | 当前作品组合的唯一身份 |
| CUT | 唯一画面基线 |
| PIC | Object ID、版本、哈希 |
| AUD | Printmaster ID、语言、声道、哈希 |
| TEXT | 字幕ID、语言、类型、哈希或不适用 |
| GFX | 图文ID、语言、Texted／Textless状态、哈希 |
| 时间 | 帧率／时间基、起点、时长 |
| 目标 | 色彩、声音、字幕和母版角色 |
| 状态 | 候选、通过、冻结或被替代 |
| 批准 | 批准者、日期、开放限制 |

一个Composition可以指向独立画面、声音和字幕组件，也可以指向已经合成或封装的文件。专业要求是逻辑绑定明确，不是强迫所有项目采用IMF或大型MAM。

### 六、Final VFX、Grade与GFX要在同一画面解释中汇合

PIC冻结前应确认：

- Final VFX确实属于当前CUT和镜头版本；
- Grade返回对应正确Conform和Stage5参考；
- GFX在正确的Input／Working／Output位置加入；
- Alpha、Matte、文字白、品牌色和透明边缘没有被错误变换；
- 烧录字幕、标题和屏幕文字在实际编码后仍清晰；
- Stage6的封装、缩放、Range、Chroma和标签没有静默改变Stage5输出。

Stage6发现颜色或图文异常时，先判断是Online、合成、编码还是Stage5来源问题；它不能用新的临时LUT掩盖责任。

### 七、Printmaster与Timed Text分别保持声音和文本身份

Printmaster是特定语言、声道布局和播放Profile下的最终声音，不是完整视频母版。Timed Text是独立语言与用途的同步文本，也不因被封装进一个容器而失去自己的版本。

Composition必须说明：

- Printmaster的语言、布局、Channel Map、起点、时长和QC；
- TEXT属于对白字幕、翻译、SDH／Caption、Forced Narrative还是其他类型；
- 字幕依据哪个最终音频完成；
- 当前母版是把字幕保持Sidecar、封装为独立轨，还是烘焙进画面；
- 不适用时明确写不适用，而不是留空让下游猜测。

本主题不重复终混、响度、字幕校对和Timing细节，只验证进入母版的对象确实是相邻主题所批准的最终组件。

### 八、Textless、Clean Plate与clean master没有统一范围

- Textless可能指移除可本地化后期文字的完整画面版本，也可能只交对应镜头的插入段。
- Clean Plate通常是去掉文字或图形后仍可重新合成的背景画面。
- clean master在不同合同中可能表示无字幕、无图文、无台标、无本地化文字或其他组合。

因此不能只写“已交clean”。最低记录应包含：对象ID、对应Texted版本、被移除元素、保留元素、镜头范围、语言、色彩解释、Alpha／Matte和用途。没有本地化或再制版需求时可以不制作复杂Textless包，但应保留字幕源、图文工程和依法可保存的必要依赖。

### 九、内部母版、交付母版、Mezzanine、发布派生和保存母版角色不同

| 角色 | 回答的问题 | 不能自动等同 |
|---|---|---|
| 内部AV-MASTER | D内哪一个完成声画图文汇合的结果是权威派生起点 | 平台上传文件、恢复包 |
| 交付母版 | 哪个文件或包满足特定接收方技术契约 | 所有平台通用母版 |
| Mezzanine／Intermediate | 哪个高质量中间层用于可靠转码、版本化和降低母版重复使用 | 面向终端带宽优化的发布编码 |
| 发布派生 | 从哪个母版为哪个平台或播放目标编码 | 内部权威母版、保存母版 |
| 保存母版 | 哪个高质量最终表示承担长期保存和未来派生 | 完整可编辑工程 |

小型项目可以让一个高质量文件同时承担内部母版、Mezzanine和保存母版的部分功能，但必须在Manifest中说明实际角色、限制和验证；一个高压缩上传文件不能因为“最终发布过”就反向成为唯一权威母版。

### 十、母版可以是文件，也可以是组件化包

跨软件流程不假设最终作品一定是一条自包含视频流：

- 简单项目可以输出一个画面与Printmaster封装完成的AV文件，并另外保存Timed Text。
- 多语言或多版本项目可以保持画面、音频和字幕组件独立，由Composition描述播放关系。
- 交付方若要求IMF、DCP、AS-11或其他包，应按相应规范制作和验证。

包结构、CPL／清单或自动验证通过，只能证明相应结构和组件关系满足规则；它不能替代人工判断是否选中了正确Grade、Mix、字幕和创作版本。

### 十一、QC必须检查实际输出，不检查时间线想象

最终QC对象必须是实际导出的精确文件或可解析的组件化包。最低回读：

1. 从交付位置重新打开，而不是继续播放导出时间线；
2. 读取容器、视频流、音频流、字幕流和metadata事实；
3. 核对文件大小、时长、帧率、画幅、色彩标签、声道、语言和字幕类型；
4. 验证Hash与Manifest；
5. 用独立播放路径播放实际解码结果；
6. 对照MASTER-COMPOSITION和Stage5／Printmaster／字幕参考；
7. 把播放器、显示和监听限制写入QC记录。

导出日志无报错只说明编码任务完成，不说明文件在另一条解码路径中仍保持正确关系。

### 十二、自动技术QC负责事实和异常候选

自动检查适合：

- 文件存在、大小、Hash、父子对象与Manifest一致性；
- 容器、编码、分辨率、帧率、时长、像素格式和标签；
- 音频采样、声道数量、Channel Map、响度和True Peak测量；
- 字幕语法、事件越界、重叠、时长和阅读速度候选；
- 黑帧、冻结、静音、丢帧、削波、不同步和像素差异候选；
- 色彩标签、Range、画幅和转码差异；
- 文件能否完整解码。

自动检查不能独立判断黑场、静默、异步、动态、色彩变化或字幕断句是否出于创作意图，也不能确认语言、表演、叙事与审美。

### 十三、OPC首圈用两遍完整人工审看

对一分钟左右AI短片，抽样比完整审看节省不了多少时间，首圈默认让同一精确母版哈希完成两遍从头到尾审看：

#### 第一遍：观众体验遍

- 正常速度连续播放，尽量不暂停或循环；
- 关注理解、注意力、情绪、节奏、声画关系和字幕阅读；
- 记录问题时间码，不在本遍立即进入修复；
- 检查片头到片尾、第一帧到最后一帧的完整体验。

#### 第二遍：技术与组件关系遍

- 再次从头到尾播放实际输出；
- 核对切点、VFX、Grade、GFX、拼写、字幕、声画同步、声道、黑场、静音、片头片尾和压缩；
- 对已记录位置暂停、倒回或使用Scopes／Meter作诊断，但仍完成全片；
- 核对每个异常对应PIC、AUD、TEXT、GFX、编码还是播放环境。

这两遍是OPC首圈的默认方法，不是全行业固定审看次数。长片、设施流程、多个语言和多个布局可采用专业QC分工、抽样加风险策略或更多轮次；但任何策略都要写明检查对象、范围和未检查项。

### 十四、QC证据必须绑定精确Master ID与Hash

最终QC记录至少包括：

| 字段 | 为什么需要 |
|---|---|
| Master／Composition ID | 防止报告落到另一版本 |
| 文件路径、大小与Hash | 定位精确字节实例 |
| 自动工具／规则版本 | 说明检测能力和阈值 |
| 人工审看者与日期 | 证明谁真实观看和核听 |
| 观看／监听条件 | 限定结论等级 |
| 完整审看遍次与范围 | 区分Full、Spot和未检查 |
| 问题时间码与对象 | 支持路由修复 |
| 修复版本与回归结果 | 证明问题真正关闭 |
| 用户决定与残余限制 | 区分通过、接受限制和未知 |

文件重新导出后Hash变化，旧QC报告不能自动继承。即使内容意图相同，也要为新字节实例建立检查记录。

### 十五、修复先判断影响半径

| 变化类型 | 典型例子 | 最小回归思路 |
|---|---|---|
| 局部元素 | 单个错字、单镜头图文边缘、一个字幕事件 | 检查修复点、镜头前后、相关组件及重新组合结果 |
| 组件范围 | Printmaster一段自动化、整条字幕轨、GFX版本替换 | 完整核对该组件并检查与其他组件的同步和覆盖 |
| 全局处理 | Output Transform、Range、Channel Map、Downmix、Limiter、编码器或缩放改变 | 重跑全文件自动QC并至少完成完整技术遍 |
| 时间结构 | CUT、切点、时长、变速、帧率或起点改变 | 所有组件Reconform，建立新Composition并重新两遍整片审看 |
| 对象选择 | 错Grade、错Printmaster、错语言或旧组件 | 旧母版作废，重新冻结组件、组合、导出和完整QC |

“修了哪一帧”不等于“只需检查哪一帧”。共享总线、全局变换、字幕重排、编码和时间变化都可能扩大影响半径。不存在适用于所有项目的固定回看片长。

### 十六、修复与回归必须形成新版本

最小修复闭环：

1. 冻结失败母版和QC报告，不覆盖；
2. 记录问题症状、时间码、对象、期望与判断依据；
3. 路由到真正拥有问题的阶段或组件工程；
4. 生成新组件Object ID并保留父版本；
5. 建立新MASTER-COMPOSITION和AV-MASTER候选；
6. 重跑适用的自动检查；
7. 对修复点和影响半径执行回归；
8. 让最终候选完成规定的两遍整片审看；
9. 生成新Hash、QC证据和批准状态；
10. 把旧版本标为Superseded，而不是删除。

直接在最终视频上做不可追溯补丁，可能短期通过但破坏下一次再输出；若因紧急交付采用补丁，仍需保存补丁来源、方法、父对象和限制。

### 十七、版本冻结是不覆盖，不是永远禁止修改

冻结对象至少包含：

- 当前Composition及全部组件ID；
- 内部母版或母版包的精确Hash；
- 输出Profile与生成日期；
- 自动和人工QC状态；
- 批准者、批准范围和残余限制；
- 被替代版本与替代原因；
- E接收对象及禁止误用的旧版本。

冻结后发现错误仍可修复，但必须建立新组件、Composition和母版。Picture Lock冻结剪辑基线；版本冻结冻结最终作品组合，两者发生在不同节点。

### 十八、Manifest与Hash只能证明一部分

Hash可以证明：

- 两个文件的字节是否一致；
- 复制、传输或存储后是否发生字节变化；
- QC报告是否仍指向同一精确实例。

Hash不能证明：

- 文件选对了CUT、Grade、声音、语言或字幕；
- 声画同步、色彩、动态和创作意图正确；
- 字体、插件、模型和许可证齐全；
- 文件未来仍能解码；
- 工程能够重开、重连和再输出；
- 作品可以合法公开。

Manifest的作用是把Hash放回对象关系中。最低应记录Object ID、角色、父对象、路径、大小、Hash算法与值、时间事实、语言／声道、Profile、状态、QC和限制。具体算法服从接收方和工具能力；不能把某一种算法写成所有项目唯一标准。

### 十九、归档前先定义恢复目标

| 恢复级别 | 最低目标 | 需要保留 |
|---|---|---|
| 母版复现 | 能重新生成当前内部母版 | 权威工程、采用组件、输出配方、依赖和参考 |
| 有限修改 | 能修字幕、图文、声音或局部画面 | 可编辑源、必要Handles、分轨／Stem和版本关系 |
| 完整再剪／再制版 | 能重建时间线、换镜头、改语言和重新制版 | 原始素材、完整工程、关键版本、全部依赖与长期管理 |

恢复级别是项目承诺，不是文件夹名称。只保留成片文件最多支持观看和部分派生，不能宣称可以恢复完整项目。

### 二十、Archive README让未来的人知道从哪里开始

最小Archive README包括：

1. 项目、CUT、Composition和冻结Master ID；
2. 权威工程入口与目录结构；
3. PIC、AUD、TEXT、GFX及父子版本；
4. 输出Profile、色彩配方、声道、字幕和编码说明；
5. 软件、插件、字体、LUT／OCIO配置、编解码器与版本；
6. AI模型／服务版本、采用生成批次、必要参数和可合法保存的来源记录；
7. 字体、音乐、素材、模型及插件的许可／可转交限制；
8. 重连规则、缺失依赖、替代方案和已知限制；
9. Manifest、Hash算法、存储位置和副本状态；
10. 恢复步骤、最近测试日期、实际结果和未测试范围。

不在恢复包中保存API密钥、Cookie、账号凭据或无法合法转交的资产。对不能打包的依赖，保留来源、版本、权利状态和替代路径。

### 二十一、工程、媒体与依赖必须一起归档

仅保存工程文件可能缺少：

- 原始或采用AI媒体、最终VFX和Grade输出；
- Printmaster、必要Stem和声音工程；
- 字幕可编辑源、翻译／术语表和Timed Text；
- 字体、图文工程、Alpha／Matte和Textless元素；
- LUT、OCIO配置、色彩配方和参考画面；
- 插件、模型、脚本、编解码器和软件版本；
- 代理与原件映射、Change List和Reconform记录；
- 批准、QC、Manifest和E交接证据。

“工程能打开”不等于媒体已重连；“媒体都在”也不等于插件、字体和变换配方可以重现。

### 二十二、多副本、Fixity与恢复测试是三种功能

- 多副本降低单一介质、设备或地点故障风险；
- Fixity通过Hash发现副本是否发生字节变化；
- 恢复测试证明工程、媒体、依赖和说明能否重新形成所承诺的结果。

OPC首圈至少让工作存储之外存在一份独立副本，并记录两份的位置与Hash状态；更高价值、长周期或委托项目再增加离线、异地或受管理副本。具体份数、介质、地点和检查周期必须按价值、预算、隐私和接收要求决定，不能把一种“3-2-1”口号当作唯一行业规范。

### 二十三、恢复测试要实际重开、重连和重输出

最小恢复演练：

1. 从工作路径之外的副本开始；
2. 先按Manifest验证文件存在、大小与Hash；
3. 在记录的软件环境中打开权威工程；
4. 按Object ID和父子关系重连，不只依赖原绝对路径；
5. 检查字体、插件、LUT／OCIO、模型和编解码依赖；
6. 输出约定的测试段或完整母版；
7. 对比时长、切点、画幅、色彩、声音、字幕和图文；
8. 若输出能够确定性复现，再比较Hash；否则使用参考画面、音频、技术事实和人工审看来证明等价范围；
9. 记录成功、失败、替代方案和未测试部分。

只完成复制和Hash校验时，应写“副本Fixity通过”；完成重开但未重输出时，应写“工程可打开，输出恢复未验证”。不得把较低级别结果升级成“完整恢复通过”。

### 二十四、Stage5专项QC与Stage6总QC是两道门

| Stage5负责 | Stage6负责 |
|---|---|
| 源色彩解释、Input／Working／View／Output | 接收已批准PIC并保持解释 |
| 监看、镜头匹配、Look和色彩专项异常 | 图文、封装、缩放、编码后的颜色回归 |
| Grade／VFX色彩往返与参考输出 | 与Stage5参考比较实际母版解码结果 |
| 色彩输出通过 | 声画字幕图文组合及全片通过 |

Stage6的颜色回归不是重新调色。若最终编码改变Range、Gamma／EOTF、Gamut、Tag、Chroma、品牌色或字幕边缘，应返回Stage5／Online修复并生成新组件。

### 二十五、D与E以“是否改变媒体本体”分界

D负责：

- Online、最终声画字幕图文组合和母版；
- 为明确目标生成技术派生；
- 对实际输出完成自动与人工QC；
- 版本冻结、恢复包、Manifest和限制；
- 向E交付唯一媒体对象及Hash。

E负责：

- 选择平台并刷新当前规则；
- 标题、文案、封面、发布字段和发布包；
- 发布前权利、隐私、AI标识与资格核对；
- 人工上传、平台预览、发布回执和发布后复盘。

若E准备重新编码、烧录字幕、改画幅、改声道或修改媒体，应返回D形成新的DELIVERY-DERIVATIVE并完成相应QC。D不因制作了技术派生就获得公开上传授权。

### 二十六、平台结果是外部派生，不覆盖内部母版

平台可能重新编码、改变色彩解释、Range、响度、声道、字幕渲染或播放增强。应分三层记录：

1. 内部AV-MASTER：D内权威结果；
2. DELIVERY-DERIVATIVE：按明确目标从内部母版转出并由D验证；
3. PLATFORM-DERIVATIVE：E上传后由平台处理的外部结果。

平台预览异常应由E记录并返回D分析；修复后生成新派生。不能用下载回来的平台文件覆盖内部母版，也不能把“上传成功”写成母版QC通过。

## 方法与案例

### 组件相同与组合相同不是同一件事

同一PIC和AUD可以以不同起点、范围、语言默认值或字幕选择组成不同观看结果。Manifest不仅保存对象ID，也要说明哪些区间、怎样映射到节目时间、哪些轨默认开启。若起点错了一秒，所有组件哈希都正确，作品仍会失步。

本库比对次序：确认组件身份 → 确认组合参数 → 检查实际输出流 → 检查解码结果与完整观看。先看容器时长和首帧只能发现部分问题；头、中、尾对应点有助区分固定偏移与持续漂移，局部改版仍须逐段核对。

### 重新封装、重新编码与修改内容的证据影响不同

重新封装可能保留压缩媒体流却改变文件字节、流顺序、默认语言或时间戳；重新编码可能改变像素／音频表示；修改字幕、图文或剪辑又改变了内容。文件哈希变化说明是新实例，不说明哪一层已经变化。

本库允许有依据地复用旧检查的结论范围，但必须新建对新实例的证据关联：例如已证明媒体内容不变时，不必伪称重新审校所有词句；仍要检查新封装的时间、轨道、默认行为和实际播放。没有等价证据时不继承。不同变化是否重做完整审看，服从项目风险与约定，不能因“只是换容器”自动跳过。

### 自动QC要区分未发现、未覆盖与确已通过

“没有报错”可能是未触发阈值，也可能是检测器不覆盖该问题。静止镜头不是必然冻结错误，创作黑场不是必然丢帧；同样，错误语言、被替换的视线或旧Printmaster可能完全可解码。

本库报告至少写实际运行的检查、输入哈希、范围、异常候选、人工判定及未检查项。修复一处后，如果重新编码或共享处理影响全片，要扩大回归；只改一个标签，也要查它影响的解码与选择行为。不可用一次工具绿灯代表声音、语言、叙事和权利全部通过。

### 同步副本不等于独立可恢复副本

两份文件若在同一故障介质，或被同一个同步删除／覆盖动作同时修改，并未隔离相应风险。保存方案应问“主要防什么”：设备损坏、误删、账号失效、格式／依赖过时，还是无法再取得生成服务。根据目标选择独立副本、版本历史、离线或其他措施，而不是只数文件夹。

[NDSA当前Levels页面](https://www.ndsa.org/publications/levels-of-digital-preservation/)将保存视为可分级建设与评估的能力；[NASA技术数据管理说明](https://www.nasa.gov/reference/6-6-technical-data-management/)还区分数据的获取、访问、变更权限、长期保留与依赖。后者是跨领域资料，本库只借其数据责任原则，不移植航天审批制度。

恢复测试也不应仅在仍能偷偷访问原绝对路径的环境里运行。可在不移动／删除原件的前提下，从独立位置、明确可见依赖集开始验证，并记录是否仍引用工作盘、云账户或未归档字体。能播放旧母版、能重连时间线、能重新渲染是不同承诺；本轮没有执行这些媒体操作。

本轮补充与读取限制见[[知识库/创作区/D-声音与后期/声音与后期专业优化/06-终混处理、声音交付与母版验证]]。

### 跨软件成片完成法

1. 确认唯一CUT、Picture Lock、离线参考和锁画后变更。
2. Online回原，逐切核对原件、Final VFX、Grade、画幅、变速和图文。
3. 接收PIC、AUD、TEXT、GFX并逐组件冻结。
4. 建立MASTER-COMPOSITION，不用最新文件名动态选择。
5. 选择母版角色和目标Profile，生成内部AV-MASTER候选。
6. 从交付位置回读实际输出，验证Manifest和技术事实。
7. 跑自动QC并保存报告。
8. 用户对同一Hash完成观众体验遍和技术组件遍。
9. 将问题路由到所属组件，按影响半径修复并回归。
10. 最终候选重新两遍审看，通过后冻结版本和QC证据。
11. 建立Archive README、依赖清单、多副本和恢复包。
12. 从独立副本重开、重连、重输出并记录真实结果。
13. 向E只交唯一对象、Hash、Profile、QC状态和残余限制。

### 一分钟AI短片综合案例

锁画版本CUT-07回原后，Stage5交付PIC-05，终混交付立体声Printmaster AUD-04，中文字幕为TEXT-ZH-03，片名和片尾为GFX-04。MASTER-COMPOSITION MC-02明确绑定四个组件，生成内部母版 MASTER-02。

自动QC发现总时长正确，用户第一遍却听到结尾音乐被截断；第二遍确认GFX片尾延长后AUD仍使用旧尾长。正确处理不是在MASTER-02上补静音或淡出，而是返回声音工程生成AUD-05，建立MC-03和MASTER-03，重新跑自动QC、两遍审看并冻结新Hash。MASTER-02保留为Superseded。

### Hash正确但对象错误的反例

文件AUD-OLD复制无误，Hash与Manifest中的旧记录完全一致，但Composition误选它代替已批准的AUD-NEW。Fixity通过并不能修复对象选择错误；必须回到组件状态和Composition引用检查。

### Burned字幕错字案例

烧录字幕在最后一遍发现人名错字。由于TEXT已经进入GFX／PIC像素，修复会生成新的TEXT、GFX或PIC组件和新母版；不能只修改字幕源后继续沿用旧视频Hash。若保留了无字幕基线和可编辑字幕源，返修范围清楚；否则可能被迫重新完成更大范围的画面输出。

### E临时转码的反例

E发现平台文件过大，若自行用任意预设转码，可能改变Range、声道或字幕。正确做法是把目标大小和平台技术限制返回D，由D从已冻结母版生成新DELIVERY-DERIVATIVE、完成实际输出QC，再把唯一Hash交回E。

### ZIP工程即归档的反例

工程压缩包可以解压，但缺字体、插件、LUT、AI原始批次和Printmaster工程，且所有路径指向已不存在的外接盘。这只能证明工程文件有副本，不能证明项目可恢复。

## OPC与Agent分工

| 任务 | Agent可主做 | 用户必须确认 |
|---|---|---|
| CUT与对象盘点 | 扫描版本、提取技术事实、生成父子图和缺口清单 | 哪个CUT和组件是当前权威 |
| Online差异 | 比较时长、切点、帧、像素和元数据候选 | 差异是错误还是有意修改 |
| 组件Manifest | 维护PIC／AUD／TEXT／GFX、路径、语言、声道、Hash和状态 | 组件冻结与开放限制 |
| 自动QC | 检测解码、标签、黑帧、静音、削波、字幕和同步候选 | 创作意图、语义、审美与接受决定 |
| 两遍审看辅助 | 提供检查表、记录时间码、分类问题和追踪回归 | 用户必须真实从头到尾观看、核听并批准 |
| 影响半径 | 根据变更传播提出回归范围候选 | 是否扩大回归及最终版本采用 |
| 版本冻结 | 生成Composition、Manifest、Hash和Superseded记录 | 冻结哪一版、谁批准 |
| 归档盘点 | 列工程、媒体、字体、LUT、插件、模型和缺失依赖 | 恢复目标、合法保留范围和风险接受 |
| 恢复测试辅助 | 验证Hash、指导重连、比对再输出事实 | 实际恢复是否达到承诺级别 |
| E交接 | 生成唯一对象、Hash、Profile、QC和限制摘要 | 哪个媒体进入发布包 |

Agent不能替用户看片核听，不能在未知语言上批准字幕，不能在未受控显示／监听上批准画面和声音，不能把自动报告当成创作验收，也不能在没有实际恢复操作时宣称工程可恢复。

## 常见误区

- 用final、final2、最终版命名代替Object ID和Composition。
- Picture Lock后静默换镜头，只让Online修画面而不通知声音和字幕。
- 看到媒体全部在线，就认为代理已经正确回到原件。
- 把Printmaster称作最终视频，或把上游Stem直接拖入母版。
- 把字幕文件语法通过当成文本、翻译和时序通过。
- 把Textless、无字幕、Clean Plate和clean master当成同义词。
- 在Stage6重新套LUT修复图文或转码造成的颜色变化。
- 只看时间线，不回读实际导出。
- 自动QC通过后省略人工完整审看。
- 只循环问题点，不重新看修复对全片关系的影响。
- 覆盖旧母版，导致旧QC报告、Hash和批准关系失效。
- 只保存高压缩发布文件，删除内部母版和可编辑工程。
- 只做副本和Hash，不测试工程重开、媒体重连和再输出。
- 让E为了文件大小、字幕或声道自行静默修改媒体。
- 把上传成功或平台预览正常写成D母版和恢复均已通过。

## Resolve 20中的输出回读与恢复练习（2026-09-12）

本次增加官方《剪辑师指南》的具体软件例子，服务已确定的母版与QC原则。片段处理、声音制作与字幕设计的详细步骤仍留在本书来源笔记及原有专业主题；本节只说明它们进入完成和恢复检查时需要证明什么。

### 处理结果进入组件前的检查

Render in Place会生成带效果的新媒体；必须知道烘焙了哪些效果、保留多少余量以及如何回到可编辑原件。Proxy、Render Cache与烘焙结果不是同一角色。后续调色或Online之前检查采用的是哪一版本，并检查插帧和动态合成的实际画面。

声音侧先区分Clip、Track与Bus处理，单个片段归一化不证明最终混音正确。主混、M&E和语言版需要实际核听：排除DIALOGUE轨仍可能遗漏SOT中的语言，或因去掉混合对白轨而留下效果缺口。字幕要分别核对文本、时间、语言和呈现方式，不能把烧录、独立文件和嵌入轨互相冒充。

### AAF、M&E总线与达芬奇导出回读验证

达芬奇导出的AAF要检查媒体、时码和接收端解释；M&E总线要分别监听并验证没有对应对白泄漏、也没有遗漏效果。两者都需要实际输出回读，不能只凭渲染完成判断。

| 输出 | Resolve内可做的回读 | 还需要的外部或项目证据 |
|---|---|---|
| 主观看文件 | 新工程重新导入，检查画面、时长、主声音、字幕 | 目标播放器/平台实际呈现和当前接收要求。 |
| 双音轨或M&E文件 | 分别Solo核听主混与M&E，确认内容与路由 | 语言版本、效果补全及接收方规格。 |
| AAF | 导回检查媒体、参考时码、范围和同步 | 接收端软件实际打开及功能兼容。 |
| 归档包 | 导入工程或时间线并回连复制的媒体 | 原依赖不可用条件下的恢复与再输出测试。 |

横竖版本先复制时间线，再修改独立设置并逐镜重构图。AI自动跟随主体不保证保留了关键行动和关系。队列修改后确认Update Job，最终以实际文件读取到的编码、音轨和字幕为准。

### 预设和归档范围要保留条件

本书的响度、True Peak、PCM、编码和24帧handles均是相应练习设置，不替代当前Output Profile。精简为已使用媒体和余量的归档只能支持其声明范围内的修改；目录存在或渲染完成不能证明未来可恢复。

## 不能泛化的规则

- Online、Grade、VFX、图文和字幕不存在全行业唯一先后顺序。
- Online Editor、Colourist、Mixer、QC Operator、Deliverables Producer和Archivist不一定由不同人承担。
- 最终母版不一定是一个文件，也不一定采用IMF、DCP、AS-11或任何固定容器。
- 内部母版、Mezzanine、交付母版和保存母版可以由同一文件承担部分角色，但不能默认相同。
- clean master没有统一定义，Textless也不表示删除所有可见文字。
- 不存在统一的字幕格式、编码、帧率、色彩、响度、True Peak、声道和Downmix参数。
- 自动检查不能统一替代人工完整观看和核听；Full与Spot QC的采用取决于合同、风险和项目规模。
- 两遍整片审看是OPC短片首圈默认，不是所有机构、片长和版本的强制遍数。
- 修复后的回归范围没有固定秒数或镜头数，取决于变化传播。
- Hash只证明字节身份，不证明对象选择、内容、同步、审美、权利或恢复正确。
- 备份副本数、介质、地点、Fixity算法和检查周期没有一套适用于所有项目的数值。
- 工程能打开不等于媒体已重连，再输出成功也不一定证明与批准母版创作等价。
- 平台上传文件和平台重新编码结果不能自动覆盖D内部母版。
- D完成技术派生不等于获得发布授权，E组装发布包也不等于可以修改媒体本体。

## 对我的创作有什么启发

1. 成片完成不是“所有专业都做完了”，而是它们以明确版本共同构成同一作品。
2. 一分钟短片的最大优势是可以用很低成本完整看两遍，不必把自动QC当成节省看片时间的理由。
3. AI素材和自动工具让文件生成更快，也让错版本、错语言、错声道和错处理更容易以“正常播放”的形式潜伏。
4. 归档价值不在保留最多文件，而在未来能找到权威入口、理解依赖、重建关系并诚实说明不能恢复什么。
5. D交给E的不是一个模糊final文件，而是一项可核对的媒体承诺；E若要改变媒体，应回到D重新形成证据。

## 复习区

### 一分钟核心摘要

阶段6先用唯一CUT和离线参考完成Online回原，再冻结PIC、AUD、TEXT、GFX，建立MASTER-COMPOSITION并输出内部母版候选。QC必须检查实际输出：自动检测技术事实和异常候选，用户对同一Hash完成观众体验遍与技术组件遍。修复按影响半径返回所属组件，形成新版本并重新回归；通过后冻结Composition、Master和QC证据，不覆盖旧版。Manifest与Hash只能证明对象关系和字节身份，不能证明内容或恢复；可恢复归档还需Archive README、工程媒体依赖、多副本和实际重开、重连、重输出。D负责媒体本体，E负责发行包装与上传。
