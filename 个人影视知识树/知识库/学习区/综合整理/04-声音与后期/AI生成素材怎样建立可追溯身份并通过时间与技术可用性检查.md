# AI生成素材怎样建立可追溯身份并通过时间与技术可用性检查

> 本主题研究AI素材进入D后，怎样先证明“它是谁、从哪里来、时间怎样运行、处理后还能否正确回到原件”，再决定能否进入创作剪辑。它解决的不是某款软件怎样导入，而是重生成、代理、转码、补帧和重连时最容易发生的静默误配。

## 快速认识

- 核心问题：怎样避免同名文件、同一V镜头的多次生成、代理和派生处理在剪辑中被误认为同一素材。
- 主要结论：AI素材必须同时保留创作镜头、具体内容、技术表示和文件实例四层身份；再用文件事实、四种时间、技术QC和重连验证建立可剪辑性。
- 学习价值：先排除“技术故障伪装成创作问题”，避免剪到后面才发现素材时长、同步、画幅或来源错误。
- 适用环节：生成前接收约束、素材下载与接收、转码与代理、项目导入、离线／在线重连、重生成替换和素材问题路由。

## 核心命题

一个可以播放的文件，不一定是一个可追溯、可解释、可重连的剪辑素材。

阶段2应先建立一道“AI素材身份、时间真实性与技术可用性接受门”：

1. 找到它服务的创作镜头与具体生成内容；
2. 保留接收原件并记录来源；
3. 读取实际文件、视频、音频、空间和时间事实；
4. 分开判断标称帧率、时间戳、内容运动和创作可用时长；
5. 检查解码、黑帧、冻结、重复、掉帧、压缩与AI异常；
6. 需要处理时建立可回溯派生表示；
7. 给出可用、限制可用、需要修复、需要重生成或停用的技术状态。

技术通过只说明素材可以安全进入创作审看，不代表用户已经决定采用它。

## 适用边界

- 本主题建立跨软件通用原理，不指定剪辑软件、编码器或固定代理规格。
- 本主题只记录色彩标签与音轨事实，不决定色彩空间、Look、对白修复或正式声音制作。
- 平台规范用于提炼身份、元数据、代理、同步和QC原则；具体文件参数不直接变成个人短片标准。
- 四层身份与“AI素材接受门”是本知识体系对专业管线的简化综合，不是现成行业统一表格。
- 当前未抽检用户真实AI素材，也未执行代理回连测试；“适合当前模型输出”的结论仍待验证。
- 静态图、图像序列、透明通道、默认静帧时长和软件侧car策略尚未独立展开。
- 本阶段不锁定未来v0.8的素材编号前缀，避免与现有C资产编号或CUT编号冲突。

## 内容导览

### 整体脉络

- 身份：把创作镜头、具体内容、技术表示和文件实例分开。
- 事实：读取容器、编码、空间、时间、音轨与色彩标签，不凭文件名和观看猜测。
- 时间：同时检查标称帧率、时间戳、独立画面节奏和实际可用动作。
- 工作媒体：区分原件、中间片、代理、优化媒体、缓存与审看导出。
- 派生：换封装、转码、解释、Conform、变速和补帧分别记录。
- 验证：用技术QC、同步检查、Relink测试和问题路由决定是否进入创作剪辑。

## 知识单元

### 一、四层身份

| 身份 | 问题 | 例子 | 变化条件 |
|---|---|---|---|
| 创作镜头身份 | 它服务哪个叙事镜头 | V023 | 只有镜头计划改变时变化 |
| 视听内容身份 | 究竟是哪次生成的画面／声音 | V023的第3次生成 | 每次重生成或内容实质改变时变化 |
| 技术表示身份 | 该内容以什么技术形态存在 | 接收原件、CFR中间片、代理 | 转码、补帧、裁切、稳定等产生新表示 |
| 文件实例身份 | 当前具体文件是什么 | 路径、大小、校验和 | 复制、移动或重新落盘时记录实例变化 |

判断要点：

- 同一个V号可以有多个不同内容版本。
- 同一内容可以同时有原件、中间片和代理。
- 同一表示可以复制到不同存储位置。
- 文件名和路径只是定位信息，不是稳定内容身份。
- 校验和只证明文件字节，不能证明镜头、同步和创作价值。

### 二、技术快照

最小技术快照建议包含：

| 层 | 字段 |
|---|---|
| 来源 | 上游V镜头、生成工具、模型、批次、采用提示词卡、下载日期、原文件名 |
| 文件 | 项目相对路径、大小、修改时间、可选校验和 |
| 容器与流 | 容器、视频编码、音频编码、Profile／Level及可读位深、色度采样 |
| 空间 | 源Raster、有效画幅、PAR、旋转／方向、项目Raster和适配方式 |
| 时间 | 精确帧率、CFR／VFR、时间基、时码率与起点、帧数、时长 |
| 音频 | 采样率、位深、声道数、轨道与同步状态 |
| 色彩 | 可读取的原色、传递函数、矩阵、范围和其他标签 |
| 派生 | 父素材、处理原因、方法、参数摘要和验证结果 |

未知就是未知。缺失标签不应由Agent或观看者猜成某个色彩空间、声道布局或拍摄帧率。

### 三、容器、编码与空间

MOV、MP4等是容器，不是视频编码。扩展名相同的文件可能封装不同编码、位深、色度采样、帧率模式和音轨。能播放不代表适合稳定剪辑，也不代表质量相同。

空间上至少区分：

- 源Raster；
- 像素宽高比PAR；
- 有效创作画幅；
- 项目Raster与画幅；
- 输出Raster；
- Fit、Fill、Crop、Letterbox、旋转和重构图决定。

“1920×1080”和“16:9”描述不同层面。软件自动适配是一个处理决定，不能被当成素材天然正确。

### 四、四种时间

| 时间 | 判断 |
|---|---|
| 标称帧率 | 文件或软件宣称多少fps |
| 时间戳节奏 | 帧间隔是否恒定，CFR还是VFR |
| 内容节奏 | 有多少真实独立画面，是否大量重复、冻结或补帧 |
| 创作可用时长 | 动作、表演、摄影机运动和连续性真正可用多久 |

此外要分开采集／生成时间戳、预期播放率、项目时间基、时码率、输出率和创作变速。23.976、24、29.97不能按模糊近似混用；VFR不是VBR；Drop-frame也不删除视频帧。

### 五、工作媒体的功能边界

| 媒体 | 用途 | 核心要求 |
|---|---|---|
| 接收原件 | 保留首次到达的真实状态 | 只读、不覆盖、可定位 |
| 编辑中间片 | 解决解码、帧率或跨软件稳定性 | 可回溯原件，核对时长、同步和元数据 |
| 代理 | 降低带宽和解码压力 | 与原件保持身份、时间、画幅和音轨对应 |
| 优化媒体 | 软件内部提高性能 | 明确软件依赖，通常可再生 |
| 缓存／预览 | 加速播放和效果预览 | 不作为唯一来源、备份或母版 |
| 审看导出 | 对应一个明确剪辑版本供观看 | 记录版本、范围、时间基与导出状态 |

代理不是备份，也不默认具有最终输出资格。

### 六、六种容易混淆的处理

| 处理 | 主要改变 | 必查结果 |
|---|---|---|
| 换封装 | 容器 | 元数据、轨道和兼容性 |
| 转码 | 编码表示 | 画质代际、色彩、声道、时码、时长 |
| 解释帧率 | 同一帧序列的播放率 | 速度、时长、音频关系 |
| 帧率Conform | 目标时间基上的帧分配 | 重复、丢弃、混帧、卡顿 |
| 创作变速 | 故意改变动作时值 | 故事与声音意图 |
| Optical Flow／ML补帧 | 生成新画面 | 遮挡、手部、边缘、纹理与物理形变 |

所有实质处理都建立派生表示，不覆盖接收原件。处理后重新检查首尾、帧数、时长、同步、动作时值、画幅和伪影。

### 七、画音同步

同步不是“按一个按钮”，而是：

1. 找到正确的画面与声音配对；
2. 用时码、板声、波形或可信事件对齐锚点；
3. 检查素材尾端或多个远端点是否漂移。

只对齐开头不能证明全段同步。AI输出若没有可信源时码和板号，更需要内部身份与事件证据。

### 八、自动检测与人工审看

自动检测适合定位黑帧、冻结、重复候选、掉帧、无法解码、帧率模式、音轨和元数据。人工必须判断：

- 静止是否具有创作意图；
- 重复是否来自合理停顿或异常填帧；
- 补帧是否破坏表情、手部、边缘、遮挡和物理；
- AI身份、道具、光线与摄影机运动漂移是否可接受；
- 缺陷能否在不改变故事事实的前提下由D处理。

Agent没有实际读取媒体和留下检查证据时，只能报告“未检查”。

### 九、技术状态

| 状态 | 证据 | 路由 |
|---|---|---|
| 未检查 | 技术快照或完整审看缺失 | 先检查 |
| 技术可用 | 当前项目时间基与播放状态正确 | 进入创作审看 |
| 限制可用 | 限制和可用区间已明确 | 知情使用 |
| 需要派生修复 | 有可回溯、可验证的处理路径 | 建派生后复检 |
| 需要重生成／补镜 | 内容或运动问题超出D可修边界 | 返回C |
| 技术停用 | 损坏、身份不明或风险不可接受 | 保留记录但不剪入 |

技术状态与创作状态应分栏维护。一个素材可以“技术可用但创作停用”，也可以“创作价值很高但技术限制可用”，后者需要用户明确接受限制。

### 十、Relink与Replace

Relink寻找同一内容或等价技术表示；Replace有意换入不同内容。二者不能用同一个“重新链接成功”掩盖。

重连后抽查：

- 创作镜头与内容版本；
- 首帧、尾帧和可用区间；
- 时码或等效时间关系；
- 帧率、帧数和时长；
- 画幅、裁切、旋转、缩放；
- 音轨与同步；
- 关键切点是否仍落在同一动作和表演。

Replace应保留旧版本并创建新时间线版本，记录替换原因和影响。

## 方法与案例

### 跨软件素材接受法

1. 保存首次下载文件为接收原件，不覆盖、不直接改名丢失来源。
2. 绑定上游V镜头、生成工具、模型、批次与采用提示词卡。
3. 为具体内容、技术表示和文件实例建立可区分记录。
4. 提取文件、视频、音频、空间、时间和可读色彩标签。
5. 核对标称帧率、时间戳、内容节奏与创作可用时长。
6. 正常速度完整播放，必要时逐帧定位黑帧、冻结、重复、掉帧、重影、压缩和AI漂移。
7. 给出技术状态；需要处理时建立派生表示并复检。
8. 若使用代理或移动媒体，执行一次重连抽查。
9. 只有技术可用或已记录限制可用的素材进入创作审看。

### AI重生成案例

V023的第1次生成动作正确但人物手部崩坏；第2次生成手部正确但摄影机尾段漂移。它们服务同一创作镜头，却是两个不同内容身份。若第2次再生成CFR中间片和低码率代理，则同一内容又有三个技术表示。任何一个文件移动到另一盘，只改变文件实例位置，不等于产生新的创作镜头。

### VFR处理案例

某AI视频显示24fps、总时长5秒，但检查发现时间戳不均，且部分画面重复。不能只改成24fps标签。应：

1. 保留接收原件；
2. 记录真实时间戳与内容节奏；
3. 若当前管线需要CFR或出现兼容/同步问题，根据明确的保时长/保速度目标建立可追溯CFR派生表示；VFR本身不等于损坏；
4. 检查帧数、时长、动作时值、重复／混帧／光流伪影和声音同步；
5. 若使用派生表示剪辑，保留回到原件的身份关系；转CFR不会自动恢复缺失动作或消除原有重复内容。

### 重连误配反例

两个模型批次都导出“video_001.mp4”。若代理和原片只按文件名重连，可能把第2批内容接到第1批剪辑点上，软件仍显示在线，却已经改变表演和动作。正确做法是同时核对内容身份、源时间关系、首尾画面、时长和上游批次。

## 时间标签、实际帧与同步异常的诊断

以下算例为本库构造。字段读取能力参照[ffprobe官方文档](https://ffmpeg.org/ffprobe.html)，帧率处理参照[FFmpeg的fps_mode说明](https://ffmpeg.org/ffmpeg.html)与[Apple Rate Conform](https://support.apple.com/en-ie/guide/final-cut-pro/ver3363b44e/mac)。具体工具字段和可用方法随版本变化，本轮不提供一键“修复全部素材”的命令。

### 时间基不是帧率，解码顺序不一定是显示顺序

**Time Base（时间基）**是时间戳计数单位；**PTS（显示时间戳）**表示呈现时间，**DTS（解码时间戳）**服务解码顺序。在含帧重排的编码中两者可以不同，不应把包的解码间隔直接判成画面显示节奏。

例如时间基1/48000秒，连续显示时间戳为0、2000、4000时，间隔为1/24秒。时间基数字48000不表示48000fps。实际检查还应记录起点、各帧显示间隔和最后一帧的持续时间；最后一帧PTS减首帧PTS不一定等于完整播放时长。

报告显示24fps或平均24fps，不足以排除局部间隔变化。反过来，小幅时间戳量化差异也不应未经容差分析便判素材异常。ffprobe能列容器、流、帧和包信息，但各层读取范围不同；“读到头信息”不等于已经全片解码或完整审看。

### 同样的240帧，两种处理会得到不同时间

假设原素材240帧、CFR24fps、每帧按该时长播放，总长10秒：

- 逐帧不增不减，重新解释为25fps：总长9.6秒，动作播放速度为原来的25/24，约快4.17%。这是速度变化。
- 保持10秒时间、改为25fps输出：需要约250个显示帧位置，要选择取样、重复、混合或生成中间帧的策略。它不等于把原240帧换个标签。

声音是否随之变速、音调如何处理，由实际管线决定；不能从视频标签推断音频已同步改变。23.976通常用于显示24000/1001的简写，记录时优先保留精确分数；也不能把它静默当24。

### CFR规范化不修复缺失的表演

**Constant Frame Rate（恒定帧率，CFR）**约束输出显示节奏，不保证每帧有新的独立内容。FFmpeg的CFR输出可通过重复或丢弃帧实现；Apple也区分就近取样、混帧与光流等方法。原本缺少的一次接触、转头或完整表情，不会因输出帧率整齐而自动补全。

VFR本身是记录方式，不必然代表损坏。如果当前剪辑/交换链正确处理且验证通过，可以保留；若需要稳定代理、交换或解决已观察问题，再创建受控中间片。先说明要保留原时长、动作时值还是逐帧序列，再选方法。

光流生成的画面可能引入手部、遮挡或物体接触错误。它总应保留父素材与处理记录；若已经改变了可感知的动作或事实，还需标明内容变化并重审创作采用，不能仅称为同内容的等价代理。原“四层身份”是管理模型，不是“处理过就永远不改变内容”的保证。

### 画音不同步先分形态，再查原因

| 观察到的形态 | 候选原因，不是定论 | 区分方法 |
|---|---|---|
| 全段近似固定偏移 | 起点、同步锚点、延迟或配对问题 | 比较多个可信事件，核对是否同一take |
| 偏差随时间逐渐增大 | 播放率/时钟差异、时间解释或变速 | 对照头中尾，检查精确率与处理历史 |
| 某点突然错开，之后固定 | 丢失/重复区段、局部剪辑或拼接 | 定位跳变前后，检查原件与派生 |
| 不规则变化 | VFR处理、分段生成或内容配对等 | 按实际帧时间与可见发声事件逐段核对 |

同一症状可以有多种原因；不要一发现漂移就拉伸整条声音。先排除播放器卡顿或监看延迟，再查录制内容。波形对齐有助寻找事件，但不单独证明口型、动作和语义对应。没有媒体时只能给诊断方案，不能给“已修复”状态。

## Resolve 20中的素材组织与代理回原检查（2026-09-12）

本次补入官方《剪辑师指南》第5、6章的操作实例，保持本主题的跨软件身份与技术接受主线，不把任何软件预设提升为全项目规范。

### 工程引用与原件分开

DRP保存工程信息，不包含原始媒体；导入素材主要建立引用。Clip Name可以由元数据变量生成，但改变显示名不等于改磁盘文件名；DRB与CSV同样不是完整媒体备份。移交时确认文件、元数据、路径及实际内容各自是否到齐。

先按项目交付目标设置时间线，再核对媒体真实规格。首次导入的改帧率提示不能代替项目判断；素材看起来灰也不能证明应该无条件套色彩管理。教材的自动色彩示例依赖其正确源元数据，来历不明或已烘焙的AI素材仍须走源身份核验。

### 代理回原片：首选原片与代理播放状态

在达芬奇里验证代理媒体是否真的回连原片，不能仅凭“首选原片”选项。应核对原片路径与身份、禁用代理后的实际播放，再判断当前使用的是原片还是代理。

| 观察 | 能证明什么 | 尚不能证明什么 |
|---|---|---|
| Prefer Camera Originals已选中 | 当前优先策略倾向原片 | 原片实际上已上线。 |
| Proxy列和路径存在 | 系统记录了代理关系 | 正在播放哪一表示、是否误连。 |
| 禁用代理后原件能够播放 | 该范围原片可用 | 全片内容、时码与所有派生完全一致。 |
| Extract Proxies完成 | 得到一套提取结果 | 图形、音频、字体和工程依赖全部到齐。 |

通过禁用代理、源路径、时码/片段身份和实际播放共同检查回原。代理、渲染缓存与Render in Place分别解决源播放、效果预计算和带效果新媒体，不共用一种“已经处理过”的身份。

### 声音映射和元数据也属于接受检查

外录多声道可能同时包含混音、吊杆和领夹，先单独听和确认映射，再决定启用哪些轨道；避免把备选麦克风全部叠加。CSV导入后抽查匹配键与合并结果。智能媒体夹的All/Any规则、子片段边界与Power Bin的跨项目范围，需要实际结果验证。
